# docs(rules): 受け箱の知見の採否を Claude が裁定し規範へ反映する

## 背景

受け箱から仕分けた知見は、採否台帳で1017件ある (2026-11-15 時点、Version 9)。人が採否を決めたのは66件で、ISSUE-144 で読む件を条件で絞っても、流入が判断を上回る状態は変わらなかった。

2026-11-15 に利用者が進め方を変えた。人の手で1件ずつ決めるのは量的に厳しいので、Claude が採否を裁定して規範へ反映する。利用者はときどき CLAUDE.md と rules を目で見て調整する。裁定に Jev は使わない (ISSUE-97 の「試験」節。使えるとしても既存の規範との重複の一次選別だけで、supports を自動では採らない)。

常時層 (CLAUDE.md) へは instruction_budget の内側なら Claude が足してよく、`BUDGET_RAISES` で予算を上げるときだけ利用者に相談する。Claude の裁定は台帳の判断の保存先へ印を付けて書き、人の判断は上書きしない。

同じ日に、設計のレビューで最初の案が採る側へ倒れると分かった (見込みで951件のうち350〜500件を採り、references が数倍に膨らむ)。利用者は厳しめの裁定と3段の置き場を選んだ。採るには積極的な証拠が要り、迷いは採らない側へ倒す。行動を変える判定は規範の段へ、道具の事実は道具ごとの参照ファイルへ置き、どちらにも入らないものは台帳 (非公開) に裁定と理由つきで残す。

開始時点の人の判断66件と、下ごしらえの見立ての一致は64件だった。ただし人が判断した件は見立てが「採る」の件に偏っていて (63件)、見立ての「保留」と「採らない」の当たり具合はこの数からは言えない。

裁定の判定表、反映先の表、手順は ISSUE-146-spec.md が持つ。各 Issue の件の採否は、その Issue のディレクトリの `<ID>-decisions.md` が持つ。
