# fix(hooks): 注入する handoff に作成時刻を添える

## 背景

`home/.claude/hooks/handoff-sentinel.py` の `handle_session` は、注入する文面を
「前セッションからの引き継ぎ (.cache/<消費後のファイル名> として保存済み)」という
一文で始める。ファイル名の時刻は `datetime.now(UTC)` を消費の瞬間に打ったものである。

したがって読み手に届く時刻は消費した瞬間だけで、引き継ぎ書そのものがいつ書かれたかは
どこにも現れない。

結果として、1 か月前に書かれた引き継ぎが、今日の日付のファイル名を添えて「前セッション
からの」として注入されうる。古さの手がかりが無いだけでなく、新しく見える方向へ
バイアスがかかっている。

## 手当ての案

`handoff.stat().st_mtime` を読んで、注入する文面の先頭へ置く。消費より前に読む必要が
ある (リネーム後でも mtime は保たれるが、順序を決めておかないと将来の変更で壊れる)。

## 経過日数を rot の指標に使わないこと

2026-09-06 の実測で、未消費の handoff は 8 リポジトリにあり、経過は 0 日から 32 日まで
散らばっていた。しかし 8 本のうち 7 本は handoff を書いた後にコミットが 1 本も無く、
リポジトリがその時点のまま凍結していた。実際に内容が古びていたのは 1 本だけである。

つまり経過日数は古さの指標ではあっても、腐っているかどうかの指標ではない。腐りを
測るなら「handoff を書いてからリポジトリが動いたか」を見る必要があり、それは
handoff の mtime 以降のコミット数で測れる (比較するときはタイムゾーンを揃えること)。

本 Issue の射程は情報を添えるところまでとし、腐りの判定は入れない。判定を入れるなら
別の Issue にする。
