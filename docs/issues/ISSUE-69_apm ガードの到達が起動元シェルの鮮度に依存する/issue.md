# fix: apm ガードの到達が起動元シェルの鮮度に依存する

## 背景

2026-08-31 に apm ガードの shim が横取りしていない状態を踏んだ。原因は起動元のシェルが古い
ことで、そのシェルは shim を PATH へ足す行が入る 3 日前から生きていた。

セッション頭の告知はこれを検出できたが、手当ての文面が誤っており再起動 1 往復を空振りさせた。
文面は PR で直したが、それは対症療法であって構造は残る。長寿命のシェルが居座る限り、
`.zshrc` への PATH 変更は無音のまま効かない。

## 機構 (2026-08-31 実測)

Claude Code は session_start でシェルスナップショットを作り、Bash ツールは毎回それを source
する。スナップショットの扱いは PATH とそれ以外で違う。

| 区画 | 出所 |
| --- | --- |
| 関数 / setopt / alias | `.zshrc` を非対話で毎回評価し直した結果 |
| 最終行の `export PATH` | Claude Code のプロセス PATH (起動元シェルからの継承) |

確かめ方は 2 つ。スナップショットには `.zshrc` が定義する関数 (`cppath` / `kill-port` /
`port-proc` など) が入っている一方、`[[ -o interactive ]]` の内側で定義するエイリアス 7 個は
1 つも無く、alias は zsh 組み込み既定の 2 個だけである。もう 1 つは PATH の側で、
`PNPM_HOME` は同日のコミットで `.zshrc` から消えているのに、その値に由来する
`Library/pnpm` が現在の PATH に残っている。

つまり `.zshrc` は読まれているが、PATH だけは最終行で上書きされる。

## 決めること

`.zshenv` へ PATH 行を移す案は成立しない。`.zshenv` は毎回読まれるが、そこで prepend した
PATH も同じ最終行に上書きされる。`settings.json` の `env` も同様で、加えて値に絶対パスが要る
ため gitleaks と config-guard の 2 層が committed な settings.json を拒む。

残る案は PATH に依存しない第 2 の横取り点を置くことである。関数はスナップショットを越えて
生き残り、PATH 上の実体より優先される。置き場は `.zshenv` ではなく `.zshrc` でよい。上の機構の
とおり `.zshrc` は毎セッション非対話で評価し直されるので、新規ファイルも新しい symlink も
SYMLINK_PAIRS の追加も要らない。

ただし射程は shim より狭い。shim は exec の瞬間に立つのでフックのパーサが届かない形
(包み込み / 変数間接 / xargs) を拾うが、zsh 関数が拾えるのは同一シェル内の直接呼び出しと
変数展開と eval までである。`bash -c` と `xargs` は覆えない。恒久策をプローブの測り直しだけに
留める選択肢も残る。

`whence -w` は型を返しパスを返さないので、3 段判定を書くなら `whence -wa` を使う。
