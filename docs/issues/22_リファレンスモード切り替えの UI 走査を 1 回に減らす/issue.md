# リファレンスモード切り替えの UI 走査を 1 回に減らす

## 背景

`home/.config/raycast/scripts/toggle-reference-mode.sh` は現在値の読み取りと適用を
別々の osascript プロセスで行うため、UI ツリーの走査を 1 回のトグルで 2 回払っている。
AX 要素の参照はプロセス境界を越えられないので、read が見つけた popup を apply が捨てて
探し直す形になっている。

Issue #20 の対応で走査を幅優先へ変え、全体 17 秒から 15.4 秒まで短縮した。内訳は
read フェーズ 8.6 秒 (ペインが開くまでの待ちが支配的で、走査を速くしても効かない) と
apply フェーズ 6.8 秒 (うち走査 4 秒)。ここで削れるのは apply 側の走査 4 秒にあたる。

## 検討した案と、決め手にならなかった理由

2 案あるが、どちらもトグルの遷移規則をどこに置くかで詰まっている。

### 単一 toggle mode へ統合する

AppleScript を「現在値が A なら B、そうでなければ C を適用する」条件適用器にして、
bash が A と B と C を渡す。走査は 1 回で済む。

問題は `next_preset` が使われなくなること。規則を bash に残したまま検証するには、
テスト側に同じ条件分岐を書くことになり二重実装になる。

### 要素の位置を read から apply へ持ち越す

read が値と一緒に UI 要素の index 連鎖を返し、apply がそれを辿る。値が期待と違えば
走査へフォールバックする。`next_preset` も現在のテスト構成もそのまま残る。

問題は index 連鎖の表現と検証をどう書くかで、UI 階層への依存が 1 つ増える。
