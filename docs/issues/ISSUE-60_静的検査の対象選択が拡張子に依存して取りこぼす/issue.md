# fix(ci): 静的検査の対象選択が拡張子に依存して取りこぼす

## 背景

shellcheck の対象選択は pre-commit も CI も拡張子で行っている。拡張子を持てないファイルは
「エラー」ではなく無検査として黙って外れる。PR #183 のレビューで発見した。

発端は `scripts/apm-guard/apm` である。PATH を横取りする shim なので `apm` という名前で
なければならず、拡張子を付けられない。新規の security guard が無検査のまま main へ入る
ところだった。

PR #183 では触ったファイル 2 件だけを網へ入れ、選択を literal のパスで列挙する形にした。
残りと、選択の仕組みそのものはこの Issue が持つ。

### 実測 (2026-08-28)

追跡下でシェバンがシェルのファイルのうち、当時 `\.sh$` に一致しなかったもの。

| ファイル | PR #183 での扱い | shellcheck の結果 |
| --- | --- | --- |
| `scripts/apm-guard/apm` | 網へ入れた (触ったファイル) | 警告なし |
| `scripts/tests/test_helper.bash` | 網へ入れた (触ったファイル) | 警告なし |
| `scripts/backup-tool/backup` | 未対応 | 警告なし |
| `home/.config/herdr/scripts/herdr-unread` | 未対応 | SC1010 (`for status in blocked done` の `done` に引用が要る) |

SC1010 は挙動としては偽陽性で、bash は `blocked` と `done` の 2 回を正しく回す (対照実験で
確認)。読みやすさの警告なので、網へ入れるなら引用を足すだけで済む。

### 選択が 2 箇所にある

`.pre-commit-config.yaml` の `files:` と `.github/workflows/test.yml` の `git ls-files` の
pathspec が同じ集合を独立に表現している。設定のコメントは「CI でもミラーする」と宣言して
いるが、一致を見る検査は無く、手で維持されている。PR #183 ではまさにこのミラーが黙って
drift した (新規 shim が両方から漏れた)。

## 決めること

拡張子の列挙を増やす形は、次に拡張子を持てないファイルが増えたときにまた黙って落ちる。
選択の規則そのものを変えるかどうかを決める。

- 案 1: シェバンで選ぶ。追跡下の全ファイルの 1 行目を見る。将来のファイルが自動で入るが、
  pre-commit の `files:` は正規表現なので探索を持てない。両方から呼ぶ 1 つのスクリプトへ
  寄せることになる
- 案 2: literal のパスを列挙し続ける。今の形。drift はするが、pre-commit と CI の
  ミラーを pin するテストを足せば黙らなくなる
- 案 3: 選択を 1 箇所に置き、pre-commit と CI の両方がそこを読む

案 1 と案 3 は同じところへ着地する可能性がある。
