# feat: 監査用の砂箱イメージを用意する

## 背景

security-audit skill (ISSUE-114 で試用中) は、対象のコードを動かして境界の越えを再現したものだけを確定にする。動かすには、上流の SKILL.md の Universal execution safety 節が挙げる制御をすべて OS で強制する砂箱を要求する。

2026-10-20 に他リポジトリのセッションから届いた試用の報告では、この砂箱を用意できず、確定は0件で候補がすべて要検証で止まった (ISSUE-114 の「full audit の試用記録」節)。

- macOS の素の環境 (sandbox-exec) では、メモリとディスクの上限を強制できない (報告者が確かめた)
- コンテナなら `--network none`、`--read-only`、`--memory` などで足りる (報告者の見立てで、イメージが無く動かしていない。報告元は OrbStack の docker を想定していた)。対象の言語の toolchain をオフラインで動かせるイメージが無かった

砂箱が無い限り、どのリポジトリで回しても確定まで進めない。

## タスク

- [ ] security-audit の砂箱の要件を上流の SKILL.md から読み、項目ごとに満たし方を決める
- [ ] 使うコンテナランタイムを決める。OrbStack から apple/container への移行を確かめる ISSUE-118 (2026-10-20 時点で未マージのブランチにある) の結論に従う
- [ ] 対象の言語の toolchain と依存をオフラインで持つイメージの作り方を決める。言語ごとに作るか、対象のリポジトリから組み立てるか
- [ ] 資源の上限とネットワークの遮断が実際に効くことを、超えるプローブを中で動かして確かめる
