# fix: node のセキュリティ修正が検知されても pin へ届かない

## 背景

`home/.config/mise/config.toml` の node は 24.18.0 のまま、24.18.1 (2026-07-28、security) と 24.22.1 (2026-10-20、security) を越えて約3か月上がらなかった。気づいたのは他のリポジトリのセッションからの報告で、手元の2つの経路はどちらも検知していた。版はこの Issue を起票した PR で 24.22.1 へ上げた。

### 実測 (2026-10-22)

- node-security-notifier (launchd、日次 18:00) の `~/.local/state/node-security-notifier/launchd.log` は、2026-07-22・07-30・10-15 に「新着 1 件を処理しました」を残している。`send_notification` は `subprocess.run(..., check=True)` で、通知の後にこの行が出るので osascript は rc 0 で返っている
- ただし rc 0 は通知センターへ渡したことしか示さず、画面に出たこと・読まれたことの証拠にならない。通知はバナーとして消え、残らない
- 同じログに `nodename nor servname provided` によるフィード取得の失敗が 2026-09 以降だけで14回ある (ログの始まる 2026-06-26 からでは34回)。既読集合は GUID で持つので後日の成功で取り返せるが、失敗は通知されずログに残るだけ
- 週次の mise-update-check (`.github/workflows/mise-update-check.yml`) の notifier を旧 pin の config に当てると、`{"has_updates": true, "compatible": 1, "major": 1}` を返し、同メジャー更新として node 24.18.0 → 24.22.1 を報告する。GitHub Issue「mise: ツール更新のお知らせ」が実際に開いていたかは未確認 (このセッションでは `gh issue list` が許可されなかった)
- mise-update-check の報告は security かどうかを区別しない。セキュリティ修正が通常のパッチ更新と同じ表に並ぶ

### 見立て (推測)

検知は2経路とも動いていて、欠けているのは「届いて、急ぎだと分かり、作業の場で目に入る」部分である。日次のバナーは消え、週次の Issue は security を区別しないまま他の更新と並ぶ。他のリポジトリからの報告に、期限や版の見張りを毎日の CI 通知からセッション開始時のプローブへ移したら通知が読まれないまま残る問題が消えた、という実測がある (下の節)。

### 受け箱から届いた報告 (2026-10-22)

他のリポジトリの2つのセッションから、この Issue の設計に効く報告が届いた。どれも報告者の実測で、dotfiles では再現していない。

- 依存する外部 CLI の期限や版の見張りを、毎日の CI 通知からセッション開始時のプローブへ移すと、通知が読まれないまま残る問題が消えた。上げた直後の gate で壊れる変更 (依存パッケージの設定形式の非対応) もその場で赤になった
- 毎日の定期ジョブに1ステップ足すだけで、新しい security リリースを検知できた。`https://nodejs.org/dist/index.json` の `security: true` のうち、pin と同じメジャーで pin より新しい版があれば失敗として記録する。gzip で約11KB、ジョブの延びはダウンロード込みで5〜6秒。空の一覧や形の崩れた要素を「該当なし」にせず失敗として扱うのが要点
- 報告者は、グローバルの mise 設定の node を 24.22.1 以上へ上げるよう求めていた。これは PR #275 で済ませた
