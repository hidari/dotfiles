# fix: .zshrc が非対話シェルへ運ぶ設定をエイリアス以外にも絞る

## 背景

エイリアスが非対話シェル (エージェントの Bash ツール等) にも効き、件数が 2 件多く返る
問題を PR で塞いだ。塞いだのは `# エイリアス` ブロックだけで、同じ経路は他のセクションも
運んでいる。

経路は Claude Code の session_start シェルスナップショットである。スナップショットは
`.zshrc` を非対話で評価した結果を literal で書き出し、Bash ツールはそれを非対話で source
する。したがって `[[ -o interactive ]]` はスナップショット生成時に false になり、ガードで
囲ったものだけが焼き込まれずに済む。

## 現状

修正後のスナップショット (エイリアスのガード適用後) を実測した結果:

- `.zshrc` が宣言する `setopt` が全数そのまま焼き込まれている
- シェル関数も焼き込まれており、`claude` は同名バイナリを shadow している

害が最も明確なのは `nonomatch` である。エージェントのシェルで一致 0 件の glob が
エラーではなくリテラル 1 件として渡る。対照として `zsh -f` は `no matches found` で
落ちる。**エラーではなくもっともらしい結果が返る**という、エイリアスの件とまったく
同じ壊れ方をする。

傍証として、Bash ツール自身がスナップショットを source した直後に
`setopt NO_EXTENDED_GLOB NO_BARE_GLOB_QUAL` を打ち消している。ハーネス側もこの経路を
危険と見なしている。

## 決めること

`.zshrc` の実際の分割線は「常に要るもの (env / PATH / 関数)」と「対話専用のもの
(プロンプト・補完・オプション・エイリアス)」である。ガードを関心事ごとに 1 本へ
引き上げると、判断がセクション単位に上がりガードの数が減る。一方で、非対話側から
関数を消すと既存の運用が壊れる可能性があるため、何を残すかは個別に決める必要がある。

`claude` 関数がエージェントのシェルでバイナリを shadow する件は、意図的に残す判断も
ありうる。決めていない状態を解消することが目的で、必ずしも消す必要はない。

## タスク

- [ ] 非対話シェルへ運ぶべきものと運ぶべきでないものを、セクション単位で仕分ける
- [ ] `nonomatch` を筆頭に、非対話で有効なままだと観測を壊すオプションを特定する
- [ ] ガードの位置を決めて適用する (関心事ごとに 1 本へ引き上げるか、現状の粒度を保つか)
- [x] `claude` 関数がバイナリを shadow する状態を残すかどうかを決める
- [ ] 決めた不変条件を bats で pin する。既存の `scripts/tests/zshrc-aliases.bats` が
      実 zsh へ渡して検査する足場を持っているので、そこへ寄せる

## 裁定 (2026-10-02)

2026-10-02の棚卸しのあと、ユーザーが次のとおり決めた。

- セクション単位の仕分け: 関数と PATH は非対話シェルへ運び、setopt (`nonomatch` / `autocd` を含む) は対話専用へ入れる。棚卸しで、エージェントのシェルで `nonomatch` と `autocd` が有効になっていると確かめた。`nonomatch` はグロブの不一致を黙って通すので、観測を壊す側にある
- `claude` 関数の shadow: 非対話シェルへは運ばない。棚卸しで、エージェントのシェルで `claude` を呼ぶと補助関数 `_claude_config_dir` がスナップショットに運ばれず落ちると確かめた。残しても動かない
- ガードの粒度: 関心事ごとに1本へ引き上げる。ユーザーのコメント: シンプルになるならやろう
- 仕分けの方針は上のとおり決まったが、セクションごとの個別の仕分けとガードの適用は実装で行う
