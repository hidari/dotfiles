# マイルストーン表への所属漏れを config-guard で検査する

## 背景

ISSUE-46 が持つマイルストーン表から Issue が漏れる事象が 3 回起きている (2026-08-28 / 09-02 / 09-04)。いずれも起票そのものは規約どおりで、漏れたのは俯瞰表への所属だけである。

この漏れは沈黙する。表は所属だけを持つので、抜けは「エラー」ではなく静かな欠落として出る。全件が入ることを数えて初めて分かる、と ISSUE-46 自身が書いている。所属を決めただけでは取りこぼしは見えない。

しかも既存のゲートを全部通る。ISSUE-74 を起票したコミット (49ac671) は config-guard scan・pre-commit・CI の 10 ジョブがすべて緑のまま main へ入り、表への追加は後続の別 PR (#198) で手当てすることになった。3 回とも同じ形である。Issue 17 と Issue 18 が扱う不整合と同じく、ディレクトリの実体と俯瞰表の記述はどちらもリポジトリ内に静的に存在するので機械検査できる。

`scripts/config-guard` の `related_refs.py` が必要な部品をすでに持っている。`tracked_issue_markdown()` と `issue_numbers()` が active Issue の集合を (`closed/` の 1 段剥がしと旧新記法の吸収込みで) 返し、`identifier_matches()` が 4 記法の吸収と `PR #N` / 他リポ前置の除外まで済ませている。新規に書くのは表と実体の突き合わせ 1 本で、取り付けは `cli.scan()` へ 1 行。`config-guard-scan` は pre-commit で `files:` を持たず毎コミット走るので、起票のコミットそのもので発火する。

## 落とし穴 (着手前に読むこと)

表の切り出しを列数で絞ってはならない。ISSUE-46 は表を 5 つ持ち、マイルストーン表と同じ列数の表が他に 2 つある。1 つの絞り方が両方向へ同時に壊れ、列数の違う M7 の細分表が丸ごと落ちて「未割り当て」が大量に返ると同時に、同じ列数の順序制約表が入って未割り当ての Issue が「割り当て済み」に数えられる。詳細は ISSUE-46 の「割り当ての検算」節が持つ。

そのうえで、**間違えても出力からは気づけない**。2026-09-04 に対照を取ったところ、対象の表 2 つを名指しした切り出し (16 行) と、h2 スコープでまとめて切った切り出し (32 行) が、未割り当ても内訳も重複計上も完全に同じ答えを返した。順序制約表にしか居ない識別子がその時点で 0 件だったためで、将来 Issue が 1 件でも表から落ちて順序制約表に残った時点から静かに割り当て済みへ化ける。件数の一致を根拠にせず、検査が何行を見たかを対照と並べること。

識別子の解決規則も決める必要がある。参照文字列で引くかぎり `上流 ISSUE-23` と `Issue 23` は記法が違うので衝突しないことを実測した。ただし `config_guard.related_refs` が使うディレクトリ名の解決規則は番号だけを見るので、そちらを流用すると上流前置の識別子が自リポジトリの同番号へ解決しうる。どちらの規則を採るかを先に決める。

ISSUE-46 自身の扱いも決める。現在この Issue だけが表の外にあり、検算は「この Issue 自身が 1」と散文で足している。検査側に自ファイルを除外する分岐を持たせると、除外集合は広がる方向にしか動かず、広がっても違反 0 件の緑にしかならない。

## この Issue の射程

漏れを止める経路は 2 つある。起票の手順へ「所属を決める」を入れる委譲と、dotfiles 側で検査して止める方法である。前者は手順の canonical が上流の `dev-workflow:in-repo-issue` skill にあるため上流への委譲になり、その裁定は ISSUE-46 のタスクが持つ。この Issue は後者だけを扱う。片方が他方を不要にする関係ではない。

## タスク

- [ ] 表の切り出し規約を決める。対象を見出しで名指しする形を既定とし、列数や表の位置を条件にしない
- [ ] 識別子の解決規則を決める。参照文字列で引く形と、番号だけで解決する既存規則を流用する形のどちらを採るか
- [ ] ISSUE-46 自身を表へ入れるか、検査側で除外するかを決める
- [ ] `config-guard` へ突き合わせを実装し `cli.scan()` へ配線する
- [ ] 変異注入で検査が効くことを確認する。表から Issue を 1 件抜いて赤くなること、および切り出しを壊したときに緑のままにならないこと

## 関連

ISSUE-46 が俯瞰表そのものを持ち、漏れの記録と検算の手順もそちらにある。Issue 17 と Issue 18 は同じく Issue ディレクトリ配下を config-guard で検査する Issue で、検査対象は重ならない。
