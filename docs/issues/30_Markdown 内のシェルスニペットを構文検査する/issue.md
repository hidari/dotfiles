# feat: Markdown 内のシェルスニペットを構文検査する

## 背景

Issue #25 の Phase 4 で実際に壊した。Issue ドキュメントの伏字化でプレースホルダを裸のシェル語へ
置いたため、`<` がリダイレクトと解釈されて手順のスニペットが構文エラーになった。bash と zsh の
両方で再現し、伏字前は通ることを対照で確認している。

このバグは既存のどの検査にも掛からなかった。shellcheck は `.sh` ファイルを対象にしており、
Markdown のコードブロックは見ない。config-guard も Markdown の本文を構文としては読まない。
検出したのはマージ前ゲートの agent で、機構ではなく人手 (エージェント) の目に依存している。

CLAUDE.md は「静的検査可能なルールはプロンプトではなく、その環境の linter か ast-grep で
記述する」と定めている。この種の壊れ方は静的検査で捕まえられる。

## 背景の補足: 対象範囲の判断が要る

ドキュメントのコードブロックには 2 種類ある。そのまま実行できることを意図したものと、
説明のために断片を示すものである。後者は単体では構文エラーになるのが正常なので、
一律に検査すると偽陽性が出る。

`bash` / `sh` の言語指定があるブロックだけを対象にする、あるいは検査対象を opt-in の
マーカーで選ぶなど、範囲の決め方を先に設計する必要がある。

## タスク
