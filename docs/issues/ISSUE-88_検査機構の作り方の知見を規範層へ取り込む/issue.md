# docs(rules): 検査機構の作り方の知見を規範層へ取り込む

## 背景

委譲元から届いた「検査機構を作るときの落とし穴」の知見を、dotfiles の規範層 (常時層の CLAUDE.md / paths 付き rules / references) へ取り込む。

材料は検証ワークフローで実測と突き合わせてある。委譲元の主張のうち 3 件は反証または解釈依存なので、そのまま規範として書かないこと。

### 反証された前提

- 「分母と分子を両方数えて突き合わせる手当てが既存に無い」は偽。`rules/testing-practices.md` が既に「数える」ことを規定し、`references/testing.md` の「範囲の穴は 3 種の変異では見えない」節が Pester の実例を分母と分子の形で持つ。新規なのは 2 点だけ — (a) 突き合わせを常設の別検査として置くこと (b) 落ちた側が列数最大という偏りの向き
- 委譲元の推測「INS-1 と INS-6 は失敗側にトリガがあるので paths 付き rules へ寄せられる」のうち INS-1 は誤り。検査機構を足すときに編集するのは `scripts/**/*.py` / `rules/*.yml` / `sgconfig.yml` / `.pre-commit-config.yaml` / `.github/workflows/*.yml` で、どの rules の `paths` にも一致しない。同型は ISSUE-48 の軸F が既に記録している
- INS-3 の新規性は解釈に依存する。`references/observation.md` の既存 3 実例はいずれもその場で書いた使い捨てコマンドなので、射程は実質すでに届いている。確実に新規なのは「ツールの出力どうしを突き合わせている限り決着しない、一次の実体へ降りて初めて付く」という決め手の方

- INS-7 の4件目〜7件目 (実測): 行やループ変数を消す変異が noUnusedLocals の効く tsc や warnings-as-errors のビルドで止まり、テストが1本も走らないまま赤に見えた報告が4件届いた。新しい手当ては、runner でビルド段の失敗を別に表示する、成果物のビルドが完了したことを確かめてからテストの結果を読む、赤くしたテストを ID で確かめる、`void x;` を置くか値だけを変える型の通る変異に替える、の4つ
- INS-8 の3件目 (実測): 同じ tx の中で「検証の前に書く」へ並べ替える変異は、検証失敗の早期リターンで rollback されるので振る舞いが等価になる。意味のある変異は「commit の後へ動かす」か「別 tx で commit する」形にする
- INS-8 の4件目〜9件目 (実測): 機構の有無で出力が変わる入力を置かないと dead pin になる形が6件届いた。鍵なしを素通しする移行期間のゲート (鍵なしでは内外とも同じ応答になるので偽の鍵で送る。レビューで見つけてコードで確かめた)、ブラウザ言語のリダイレクト (既定の locale のままでは保存の機構を外しても同じ遷移先)、一覧の絞り込み (1件のあいだは非一致の項目が無く、2件目を足すと赤。全文検索が本文も見るので、絞り込みの語が他方の本文に当たらないことも実データで確かめる)、「起きないこと」のテスト (差の出ない前状態では世代を捨てる変異でも緑)、ast-grep の rule-test (前方一致の別の名前の mod を valid に置いても、中に構築の式が無いとアンカーを外す変異が緑) である
- INS-18 の2件目 (実測): 変異版で失敗が出る率が10回中2回だと、直していなくても10回中0回になる確率が約11%あり、直した版の0件に判別力が無かった。待ちを無くして1回あたりの対象を増やし、変異版の率を30回中9回へ上げると、その確率は約0.002%になった。0件を主張する前に、変異版の率から判別力を計算する
- INS-18 の3件目 (実測): 揺れの切り分けで、変異を続けて回す負荷が唯一の再現手段で、何も変えずに数回回しても再現しなかった。「何も変えずに緑」を揺れが無い証拠にしない
- INS-24 の2件目 (実測): 正規表現の選択肢をまとめて数える件数検査は、片方が2個で片方が0個でも通る。前提を疑う担当の設計案は不採用だったが、この穴を見つけた
- INS-24 の3件目 (実測): テストの実行 ID の集合の差で消えた例を1件ずつ移し先と対応づけると、移し先のほうが主張の弱い例 (2つの値のうち1つしか見ない) が1件見つかった。件数では見えなかった
- INS-24 の4件目 (実測): テストファイル1本だけを回した出力を、ディレクトリの全テストが走ったかを見る ID の照合器へ渡すと、変異なしの対照まで赤になり、取り付けを外す変異の結果が読めなかった。照合器の出力を対象ファイルの ID の行だけに絞ると、対照0行、変異6行で読めた
- グローバルの CLAUDE.md の委譲カテゴリにある「実験はリポジトリ本体ではなく隔離コピーで行わせる」の実例 (実測): 読むだけのレビューの subagent を、作業ツリーをその場で書き換える変異注入と並行で走らせると、レビュー役が変異の入ったファイルを読んだ。このときは指摘に混ざらなかったが、混ざれば存在しない欠陥を報告する。報告者の手当ては、再生が終わってから出すか、`git show <sha>:<path>` でコミットの中身を読ませること
