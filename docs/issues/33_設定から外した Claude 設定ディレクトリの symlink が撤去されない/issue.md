# fix: 設定から外した Claude 設定ディレクトリの symlink が撤去されない

## 背景

Issue #25 Phase 3b のマージ前ゲートで検出した。`prune_stale_symlinks` は走査する
親ディレクトリを「今の target 集合」から導出するため、target とその親ディレクトリが
同じ編集で一緒に消える削除イベントを原理的に見られない。

最も実害があるのはアカウントの退役である。`claude-config-dirs` から行を消して
ディレクトリを残すと、その設定ディレクトリ向けの mirror リンクは target 集合からも
走査集合からも同時に消え、二度と訪問されない。リンクは実体解決に成功し続けるので、
共有をやめたつもりの設定ディレクトリがリポジトリの `settings.json` 等を共有し続ける。
「配列から消えた pair の残骸を片付ける」というこの機構自身の目的を「設定から消えた
ディレクトリ」へ一般化しただけの事象であり、機構が最も守るべきケースが盲点になっている。

同型の盲点が 2 つある。

- ディレクトリ内で最後の pair を消したとき。例えば `.config/git/.gitignore_global` は
  `.config/git` 唯一の target なので、この pair を消すと同じ編集で走査対象からも
  `.config/git` が消え、残骸が永久に残る
- リポジトリを移設したとき。所有判定が「readlink が現在の `$DOTFILES_DIR` 前置」なので、
  旧パスを指す残骸は「うちの物ではない」扱いになり掃除されない

なお「張った記録 (manifest) を持つ」方式は採らない方がよい。記録は実体と drift する
メタデータで、CLAUDE.md が `.highwatermark` の実害で禁じている型にあたる。記録以前に
張られたリンクを掃除するには結局走査が要るので機構も二重になる。

代わりに、走査候補へ「ディスク上に実在する追加設定ディレクトリ」を合流させる stateless
な拡張なら、記録を持たずに退役の経路が閉じる。この検査は `bootstrap.sh` と
`home/.zshrc` で既に 2 箇所使っている `find $HOME -maxdepth 1 -type d -name '.claude-*'`
そのものである。

ただしこの glob は ISSUE-49 で共有実体 (`CLAUDE_SHARED_DIR`) を除外するよう変わった。
共有実体は同じ名前空間に住むが設定ディレクトリではないため、除外を落として走査候補へ
合流させると、退役していないディレクトリを退役候補として扱うことになる。実装時は除外を
引き継ぐこと。

この拡張には副次的な効果がある。現状の「設定ファイル不在なら撤去を skip する」ガードは、
走査先も同じ集合から導出される以上、防ぐと書かれている誤撤去が起き得ないため実質的に
空振りしている (この構造は `symlink_scan_dirs` のテストが pin 済み)。走査を拡張して初めて
このガードは実際に守るものを持つ。
