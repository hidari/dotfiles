# fix(hooks): apm ガードのコマンド位置判定が改行とバッククォートで外れる

## 背景

`home/.claude/hooks/apm-install-guard.py` は、ツリーが汚れている状態での `apm install` を
止めるガードである。判定は「トークン列の中で `apm` がコマンド語の位置にあるか」で行う。

この位置判定が複数の形で外れる。起票時はフックを走らせた結果だけで表を作ったが、その後
fake apm を PATH の先頭に置いて「実シェルで apm が本当に exec されるか」を ground truth と
して測り直した (bash / zsh / sh / dash / bash --posix)。以下は測り直した後の表である。

| 入力 | 実シェルで exec されるか | フックの判定 |
| --- | --- | --- |
| `apm install` (対照) | される | deny |
| `apm install; git status` (対照) | される | deny |
| `echo "apm install"` (対照) | されない | 素通り (正しい) |
| `apm view` (対照) | される | 素通り (readonly の allowlist。正しい) |
| `echo hi` + LF + `apm install` | される | 素通り (漏れ) |
| `echo hi` + CRLF + `apm install` | される | 素通り (漏れ) |
| `` echo `apm install` `` | される | 素通り (漏れ) |
| `bash -c 'apm install'` | される | 素通り (漏れ) |
| `sh -c 'apm install'` | される | 素通り (漏れ) |
| `eval 'apm install'` | される | 素通り (漏れ) |
| `echo hi # x` + LF + `apm install` | される | 素通り (漏れ。起票時に挙げていなかった) |
| `echo hi` + 単独 CR + `apm install` | されない | 素通り (漏れではない) |
| `echo hi \` + LF + `apm install` | されない | 素通り (漏れではない) |
| `echo $(apm install)` | される | deny (起票時に漏れとして挙げたが誤り) |

### 起票時の記述のうち実測で覆ったもの

| 記述 | 実測 |
| --- | --- |
| 単独 CR 区切りは漏れである | 5 つのシェルで apm は exec されない。CR は IFS にもメタ文字にも入らず 1 語になるだけ。CRLF が通るのは LF が単独で区切るためで、CR を区切りとして扱う必要はない |
| 包み込みは 1 トークンにまとまる | `$( )` は `$` と `(` に割れ `(` が演算子として効くので現行でも deny になる。1 トークンにまとまるのはバッククォートと `sh -c` / `eval` の引数だけ |
| 先頭が LF の形は機序と一致する正常な deny | 現行では deny だが、トークナイザだけを直すと `\n` が「演算子でない普通の語」として残り deny から素通りへ回帰する |
| (記載なし) | `shlex` の `commenters` が既定で `#` のため、コメント走査が行末の LF を食う。実シェルでは後続行の apm が exec される |
| (記載なし) | 行継続は `\` + LF が 1 語へ連結されるだけなので apm は exec されない。止める必要が無い |

### 機序

`is_command_position` は「直前のトークンが演算子ならコマンド位置」と判定する。演算子の判定は
`_PUNCTUATION_CHARS` に列挙した文字だけで構成されたトークンかどうかで行う。

ここに LF が入っていない。LF は shlex にとって単なる空白なのでトークンにならず、`apm` の
直前には普通の語が残る。結果としてコマンド位置ではないと判定される。バッククォートも列挙に
無いため語へ密着し、`sh -c` 系はクォート内が 1 トークンにまとまって中身が走査対象から外れる。

もとは「`shlex.split` はシェル演算子を切らない」という欠陥を `punctuation_chars=True` で
塞いだ結果である。塞ぎ方が「演算子を文字の集合で定義する」形だったため、文字ではない区切り
(LF) と、punctuation に含まれない記号 (バッククォート) が漏れた。

### 実害の範囲

このガードは security guard ではなく事故防止で、`apm install` が deploy 先を上書きして
未コミットの変更を消すのを止めるためにある。すり抜けても壊れるのは自分の作業ツリーで、
権限昇格や情報漏洩には繋がらない。

ただし「ガードがある」という前提で手順を組むと、すり抜ける形を踏んだときに前提が崩れる。
特に LF 区切りは複数行のコマンドを 1 回の Bash 呼び出しで流すときに自然に発生する。

## 方式: パースを広げるのではなく判定点を exec 時へ移す

パースを広げる方向で 26 ケースまで試した。区切り集合の拡張、`commenters` の無効化、
`sh -c` / `eval` の再帰展開、シェル予約語の語区切り、wrapper 集合の拡張を順に足したが、
変数間接・`xargs`・`find -exec`・リダイレクト先行が残り、`until` ループでは逆に誤検出が出た。
どれも「集合にもう 1 語足す」で潰せるが、その先も同じ形で出続ける。

そこで判定点を「コマンド文字列をパースする時点」から「apm が exec される瞬間」へ移す。
PATH の先頭に `apm` という名前の shim を置き、実物へ委譲する前に判定させる。
shim は文字列がどう書かれていたかに依存しないので、包み込みも変数展開も区別せず捕まえる。

### フックは撤去せず役割を変える

shim を迂回できる形が 2 つある (いずれも実測)。

| 形 | shim | フック |
| --- | --- | --- |
| `<絶対パス>/apm install` | 迂回される | deny (basename が `apm` なので現行のまま捕まえる) |
| `PATH=<別の場所> apm install` | 迂回される | deny (環境変数代入をスキップして `apm` を見るので現行のまま捕まえる) |

逆に shim だけが捕まえる形も実測した。base64 を経由する形、シェル関数定義、`xargs` へ
bare 名で渡す形、変数が bare 名を持つ形、プロセス置換。これらはパースをどう広げても届かない。

したがってフックのパースは拡張しない。フックの役割を「shim が迂回される 2 形を捕まえる」と
「shim が配置されているかを実行時に確かめる」に限定する。

### 両層をすり抜ける形 (受容する)

| 形 | 理由 |
| --- | --- |
| `C=<絶対パス>; $C install` | 絶対パスなので shim を迂回し、変数間接なのでフックの文字列走査にも掛からない |
| `python3 -c` から subprocess で絶対パスを起動 | 同上 |
| バイナリをコピーしてから実行 | 同上 |
| `find ... -exec {} install \;` | 同上 |
| `echo install \| xargs <絶対パス>` | 同上 |

いずれも「絶対パス・コピー・subprocess で実物を直接叩く」形であり、事故として自然発生しない。
このガードの目的は事故防止なので脅威モデルの外に置く。パースを広げる方式でも同じく残るため、
方式の選択を左右する差ではない。

### 配置の保証

配置漏れが「静かな素通り」になるのを避けるため、3 層で保証する。

| 層 | 保証すること | 保証しないこと |
| --- | --- | --- |
| `bootstrap.sh` の `SYMLINK_PAIRS` と `.zshrc` の PATH 行 | 実行すれば shim と PATH 設定が配置される | 実行し忘れ、shim の消失 |
| bats と config-guard | リポジトリ側に配線が存在すること | ローカルの実配置 (CI にホーム環境が無い) |
| フックの実行時検出 | フックがパースできる形での配置漏れが deny として見える | フック自体が無効化された場合。shim だけが担当する形 (包み込み・変数展開・xargs) での配置漏れ |

PATH への差し込み位置には制約がある。`.zshrc` の `path` 配列の先頭へ足しても、後続の
`eval "$(mise activate zsh)"` が PATH を再構成するため実物より後ろへ落ちる (実測で 31 番目)。
`mise activate` の直後に prepend すると先頭に入る。

3 層目には射程の穴がある。フックは `guarded_command` がパースできた形にしか到達しないので、
配置漏れの検出も同じ形にしか効かない。shim 不在でフックへ 6 形を投入した実測は次のとおり。

| 形 | shim 不在時のフック |
| --- | --- |
| `apm install` | deny |
| `/opt/homebrew/bin/apm install` | deny |
| `PATH=/usr/bin apm install` | deny |
| `bash -c "apm install"` | 無音の素通り |
| `X=apm; $X install` | 無音の素通り |
| `echo install \| xargs apm` | 無音の素通り |

deny になる 3 形はフックが自力で捕まえる形と一致する。つまり配置漏れ検出は shim が要らない
場所でだけ働き、shim だけが担当する形では働かない。「配置されているか」はコマンド単位ではなく
セッション単位の事実なので、正しい置き場は SessionStart の behavioral canary になる。これは
ISSUE-56 が残した「検査が沈黙している状態を検出する層」と同じもので、派生 Issue で扱う。

### 変異注入

3 種 (検査対象 / 検査機構 / 取り付け) に緩めすぎ方向を加えた 10 件を 1 件ずつ隔離して当て、
すべて kill した。

| 変異 | 種別 | 結果 |
| --- | --- | --- |
| shim の解決判定を常に真にする | 検査機構 | kill |
| main から shim 検査を外す | 取り付け | kill |

| shim の拒否を素通りへ変える | 検査機構 | kill |

### 途中で見つけたテスト側の欠陥

shim を起動する PATH の組み立てを間違えており、shim が一度も走らないまま実物が直接
呼ばれていた。委譲を期待する 10 件はそれでも緑になり、拒否を期待する 1 件だけが落ちた。
壊れた対照が「もっともらしい不一致」を返して対象側の欠陥に見える形である。

最初の手当て (実物側で PATH に guard が残っているかを見る) は dead pin だった。配線が
壊れた場合は guard がそもそも PATH に無いので、「PATH から外れている = shim を通った」
という判定が破損と正常な委譲を区別できない。変異注入で赤が 1 件しか出ないことから
気づいた。起動前に配線そのものを確かめる形へ替え、同じ変異で 7 件が赤くなることを確認した。
