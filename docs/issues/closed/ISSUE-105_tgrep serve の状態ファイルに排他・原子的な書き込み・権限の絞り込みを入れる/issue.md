# fix: tgrep serve の状態ファイルに排他・原子的な書き込み・権限の絞り込みを入れる

## クローズ理由 (2026-09-24)

直す対象のコードが無くなったので閉じる。tgrep を環境から撤去し (rg で検索の速度が足りるという判断による)、同じ変更で `home/.claude/hooks/tgrep_serve_state.py` と serve を起動・停止する hook を削除した。
ISSUE-102 の実装は作業ブランチ上にあるうちに撤去したので、main へは一度も入っていない。

## 背景

ISSUE-102 が入れた参照カウント (`home/.claude/hooks/tgrep_serve_state.py`) は、root ごとの
状態ファイルに生存セッションの PID を持ち、SessionEnd と SessionStart の停止判定がそれを数える。
ISSUE-102 の最終レビューが堅牢性の欠けを 4 つ挙げ、1 つのまとまりとしてこの Issue へ切り出した。
いずれも今日の運用では害が「止めない」側か「早く止める」側に落ち、早く止まった側は
`home/.zshrc` のラッパーが `--no-index` へ落として告げるので、黙った誤答にはならない。

- `register` / `unregister` は read-modify-write で排他が無い。同じ root で SessionStart が
  並ぶと、後から書いた側が先の登録を落とす (last-writer-wins)。過少計上なので serve が早く止まる
- `_write` は原子的でない。書きかけを読んだ側は壊れた JSON を空として扱い、`handle_end` では
  空の読みが「生存 0 → 止める」になる
- 状態ディレクトリとファイルのモードが 755 / 644 で、中身 (リポジトリの絶対パスと PID) を
  同じマシンの他ユーザーが読める
- 参照カウントに daemon が起こす `claude bg-spare` の PID が入る。spec のセッションモデル
  (1 PID = 1 つの cwd で動く 1 つの対話セッション) はこれを記述していない。向きが「止めない」側
  なので今日は無害だが、未記述のまま

## 方向 (着手時に確かめる)

- 排他: 状態ファイルへの read-modify-write を `fcntl.flock` で囲う
- 原子性: 一時ファイルへ書いて `os.replace` で置き換える
- 権限: 状態ディレクトリを `mkdir(mode=0o700)` で作る。既に緩いモードで存在するディレクトリを
  どう扱うかも決める
- `bg-spare`: 数えるか外すかを決め、spec のセッションモデルへ書き戻す

状態ファイルの寿命 (使われなくなった時点で消す) は ISSUE-26 の決定と揃える形を ISSUE-102 の spec が
持つので、ここでは寿命を変えない。
