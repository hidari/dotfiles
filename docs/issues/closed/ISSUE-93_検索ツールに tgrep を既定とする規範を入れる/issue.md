# agent: 検索ツールに tgrep を既定とする規範を入れる

## 背景

2026-09-12 にユーザーから「既存の Grep ツールや `grep` ではなく `tgrep` を積極的に使ってほしい」と
明示的に指示された。agentic-coding-tools 側はこれを project memory へ記録したが、memory は
プロジェクト単位でしか効かず他のリポジトリには届かない。全リポジトリへ効く canonical は
user CLAUDE.md なので、規範の起票と実装が dotfiles へ委譲された。

道具そのものの配線は PR #215 の副産物として済んでいる。`home/.Brewfile` が `tgrep` を宣言し、
索引キャッシュ `.tgrep/` の ignore は `home/.config/git/.gitignore_global` にある (このリポジトリ
限定のツールではないので repo 側ではなく global へ置いた)。足りないのは規範だけ。

規範が要るのは速いからではなく、外したときに劣化を申告しないため。速度のためだけなら道具を
入れた時点で目的は足りている。返り方の詳細と、初回に書いた rc の記述が誤っていた経緯は下の
実測節が持つ。

## 実測 (2026-09-13、このリポジトリの常駐サーバーに対して)

前セッションの観測を根拠にせず自分で再現した。probe は追跡外の作業ディレクトリに書いたので
残らない。再現に要る条件は各節が持つ。

初回の probe は 2 箇所を誤っていて、並列レビューの指摘で気づいて取り直した。訂正の内容は
下の「初回の probe が誤っていた点」節が持つ。以下は取り直した後の値。

### 常駐索引は dot 始まりを含まない

| 値 | 実測 |
| --- | --- |
| 追跡ファイル総数 | 373 |
| dot コンポーネントを持つもの | 85 |
| 差 (可視ファイル) | 288 |
| `tgrep status` の `Files:` | 288 |

成り立つのは等式の方で、件数はこの時点のスナップショットにすぎない。

これは設定で変えられない。`tgrep serve --hidden` は起動せず rc 2 で拒否する。
同じ場所でフラグ無しの `serve` は常駐したので、拒否は「その場所で起動できない」ではなく
`--hidden` に対するものだと切り分けた (probe は使い捨てディレクトリで起動し、常駐は残していない)。
`serve --help` は `--hidden` を列挙するので、ヘルプだけ読むと通ると誤解する。

### 同じ語を 2 経路で引くと結果が割れる

probe には「追跡下で 1 ファイルにしか無く、そのファイルが dot 始まり」を満たす語を選んだ
(`gitleaks_version` / `.github/workflows/test.yml`)。最初に選んだ語は dot 始まり以外にも
出現していて交絡したので、選び直している。

| 経路 | ヒット | stderr |
| --- | --- | --- |
| ディレクトリ走査 (常駐索引) | 0 | 0 行 |
| ファイル自身を明示パスで渡す | 1 | ― |
| 対照: 可視ファイルにも現れる語をディレクトリ走査 | 27 | ― |

対照が非 0 を返すので、0 件は「経路が壊れている」ではなく「索引が dot を持たない」を意味する。
stderr は 0 行で、索引の外を見ていないことは既定の出力に現れない。

対照側も同じ穴を踏んでいる。`SYMLINK_PAIRS` は `git grep` で 32 ファイルなのにディレクトリ走査は
27 件しか返さない。差の 5 件が hidden 配下にある。

**この Issue 自身が `gitleaks_version` を追跡下の可視ファイルへ入れたので、マージ後に同じ probe を
再実行すると経路 A が 1 件返る。**前提が崩れるのであって、記録が反証されたのではない。

### 明示パスが届く範囲

明示パスが通すのは書いた dot コンポーネント自身だけで、その下では hidden 除外が引き続き効く。

| 渡したパス | 走査 | 結果 |
| --- | --- | --- |
| `home` (可視の親) | 2 files | 0 件。`git grep` は同じ語で 5 件返す |
| `home/.claude` | 25 files | 3 件。`git grep` と一致する |
| `home/.config` | 33 files | 0 件。配下の `git/.gitignore_global` が dot ファイル |
| `home/.config/git/.gitignore_global` | 1 file | 2 件 |

dot ファイルを見たいときは、そのファイル自身を渡すしかない。可視の親を渡して「明示パスで
引いた」つもりになると同じ 0 件を掴む。しかもそのとき出る警告は `no index at ...` で索引の
不在を語るので、hidden 除外だとは読めない。

### 検索時の `--hidden` は索引を捨てる

`--stats` が経路を直接申告する。所要時間は交互に 3 回ずつ測った。

| 形 | `--stats` の申告 | 所要 |
| --- | --- | --- |
| 既定 | `(via server)` | 32-35 ms |
| `--no-index` | `Brute-force ... (289 files)` | 66-67 ms |
| `--hidden` | `Brute-force ... (531 files)` | 1243-1304 ms |

索引を捨てるコストは 2 倍程度にすぎない。`--hidden` の 40 倍は走査量が効いていて、
差の 242 files には `.git/` 配下が入る (実際 `--hidden` を付けると `.git/HEAD` や
`.git/logs/` の行がヒットに混ざる)。

警告は非対称で、索引の無いディレクトリを明示すると 2 行出るのに、同じディレクトリへ
`--hidden` を足すと 0 行になる。

### パイプの stdin を読まない

`printf '... SYMLINK_PAIRS ...' | tgrep --stats SYMLINK_PAIRS` は stdin を無視して
カレントディレクトリを検索し、212 件を `(via server)` で返した。渡した 1 行は出力に含まれない。
もっともらしい別物が返るので、パイプが効いていないことに気づけない。

### 0 件は rc 1 で返る

| 形 | rc |
| --- | --- |
| 存在しない語を直接 | 1 |
| 存在する語を直接 | 0 |
| 存在しない語をパイプ経由 (`\| wc -l`) | 0 |

rc は「索引の外による 0 件」と「真の不在」を区別しない。判定には `--stats` の走査数を使う。

## 初回の probe が誤っていた点

並列レビュー (Fable 3 本) が独立に同じ 2 点を突いた。どちらも「観測は正しいが結論がその観測の
届く面を超える」型で、このリポジトリが `feedback-conclusion-exceeds-the-observed-surface` として
記録している形にあたる。

### rc を `| wc -l` の後ろで取っていた

`dir_hits=$(tgrep ... | wc -l); dir_rc=$?` と書いたので、取れていたのは `wc` の rc だった。
そこから「どの面で外しても rc 0 で成功する」と書いたが、`tgrep` 自身は 0 件で rc 1 を返す。
足そうとしている規範カテゴリの「成否が隠れる」を、その規範を書く probe で踏んでいた。

### 所要時間を判定手段にした

`--stats` というフラグがあり、経路 (`via server` / `Brute-force search`) と走査ファイル数を
直接申告する。申告する手段があるのに代理指標へ逃げていた。

しかも代理指標として不適切だった。34 ms から 1381 ms への 40 倍は「索引を捨てたコスト」では
なく走査量で、索引を捨てるだけなら 32 ms から 66 ms にしかならない。時間では索引経由と
`--no-index` を分けられない。

## 置き場所の判定

`home:context-loading-mechanics` の判定基準は「その規範が回避したい失敗の側で、一致するファイルの
Read が起きるか」。この規範が回避したい失敗は「`grep` で引いて偽陰性を掴むこと」で、その瞬間は
まだ何も Read していない。したがって `paths` 付き rules へはスコープできない。同 skill が
「シェルの使い方やコマンドの組み立てに関する規範も移せない」として挙げている型と同じ。

Read を必要としない層 (PreToolUse フック) は別に存在するが、これは下の「採らなかった案」で扱う。

常時層に置くのはトリガ文と判定文だけで、一次実測は `home/.claude/references/observation.md` が
持つ。カテゴリの H2 と observation.md の H2 が 1 対 1 で対応する既存の構造に合わせる。

置き先のカテゴリは `## [MUST] 観測した結果がその主張の証拠になっているか確かめ、観測自体を加工や
連結で壊さない`。3 点とも「検査が劣化しても劣化を申告しない」形で、このカテゴリが既に持つ
「0 件・空・緑を健全の根拠にする前に」と「検索キーの偽陰性」の延長にあたる。

## 制約

- tgrep の内部仕様 (poll 間隔・reconcile 時間・索引ファイルの構成・具体的なミリ秒数) を常時層の
  散文へ再掲しない。CI が捕捉できない形で drift する
- 常時ロード層は現在ちょうど予算上限 (27030B) なので、追記すると必ず config-guard が赤くなる。
  `ALWAYS_LOADED_BUDGET_BYTES` を実態へ合わせて引き上げ、`BUDGET_RAISES` へ (日付, 引き上げ後の値,
  理由) を 1 行足す。許可条件の canonical は `budget_ratchet.evaluate_ratchet`
- 予算は実態から 2000B 以上離せない (`test_budget_tracks_the_real_repo_closely`)。余裕を持たせず
  書いた分ちょうどに合わせる

## 採らなかった案

いずれもユーザー裁定で確定済み。自然に再提案される種類なので理由を残す。

### `permissions.deny` へ bare `Grep` を入れる

不採用。理由は 3 つで、索引の無いリポジトリで詰まる、リポジトリ外を探せない、Explore など
Grep に依存する組み込み subagent がある。pnpm の規範は deny を canonical にしてその手前で
読ませる構成だが、検索ツールでは deny 側が成立しない。

### 常時層を削って相殺する

不採用。予算は引き上げる。

### scoped rule (`paths` 付き rules) へ逃がす

成立しない。上の「置き場所の判定」のとおり。

### PreToolUse フックで機械的に止める

採らない。ただし成立はする層なので記録を残す。

`tgrep ... --hidden` (サブコマンド無し) と `... | tgrep` はどちらもコマンド文字列だけで決まる
決定的な形で、Read を必要とせずまさに実行しようとした瞬間に発火する。共有インフラも既にあり、
`home/.claude/hooks/apm-install-guard.py` が `shlex.shlex(..., punctuation_chars=True)` で
パイプを独立トークンとして切るところまで持っている。`~/.claude/rules/markdown-practices.md` の
「静的検査可能なルールはプロンプトではなく linter か ast-grep で記述する」にも合う。

採らない理由は、同じ `apm-install-guard.py` の docstring が「シェル文法の近似は終わらない
(26 ケース中 7 件が残り、区切りの集合を広げるたびに新しい形が出た)」と実測を記録していること。
フックは必ず部分的になり、部分的なフックは「止まらなかった = 安全」と読まれる。
エントロピーを増やす解を却下した ISSUE-92 の判断とも揃う。

再発したときの正しい層はここなので、そのときは散文を増やすのではなく既存ガードへ 1 規則を足す。
