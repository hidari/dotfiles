# test: cppath 関数のテストを追加する

## 背景

`home/.zshrc` の「シェル関数」セクションへ `cppath` を追加した。パスを絶対化し、
`print -D` でホームディレクトリをチルダへ畳んで `pbcopy` へ流す。引数を省略すると
カレントディレクトリが対象になる。追加時点ではテストを付けていない。

同セクションの `port-proc` / `kill-port` もテストを持たないので慣行としては一貫している。
ただし `cppath` はこの 2 つと違い出力を持ち、ホーム配下とホーム外で結果が変わる。境界は
仕様として表現する価値がある。

### テストを書く前に方式の判断が要る

このセクションは既存のテスト基盤の射程外にある。`scripts/tests/test_helper.bash` の
`load_zshrc_claude_functions` は marker slice 方式で、`# Claude Code 起動` から次の
区切り行までを切り出して source する。`cppath` はその手前のセクションにあるので
読み込まれない。

射程外である理由はセクションの位置だけではない。`home/.zshrc` の `_claude_task_list_id`
には「zsh の modifier (`${dir:t}`) は bats が bash で source すると壊れるので使わない」と
コメントがある。Claude Code セクションが bash から source できるのは、この制約を守って
書かれているためである。`cppath` は `${1:a}` と `print` という zsh 専用の構文を使うので、
その制約の外にある。

ここに罠がある。bash で source すると `print` が `command not found` で落ちるため、
`printf` へ書き換えて通す経路に手が伸びる。しかし残る `${1:a}` は bash では引数を
そのまま返して exit 0 になり、絶対パス化が起きないまま静かに通る。この状態で書いた
テストは「bash 版の挙動」を pin する。CLAUDE.md の「対照は検証対象と同じ規約で作ること」が
扱っている失敗の形そのものなので、bash から読ませる方向は採らない。

`pbcopy` へ流す副作用の観測方法も決める。関数は標準出力へ何も出さないので、`PATH` の
先頭にスタブを置いて受け取った内容をファイルへ書く形が要る。このとき前置は `.zshrc` を
source した後で行うこと。`.zshrc` は中で `PATH` を再構築するため、先に前置すると押し出されて
本物の `pbcopy` が呼ばれ、実クリップボードを壊す。実際に踏んだ。スタブが有効になったことを
`command -v pbcopy` で確かめてから本体を走らせる。

### 実測で絞れている選択肢

- marker block を増やす必要はない。「シェル関数」セクションの区切りは `load_marker_block`
  がそのまま食える形をしている。足りないのは `load_zshrc_claude_functions` の隣に置く
  zsh ランナー 1 つだけである
- 別ファイルへ切り出してガード方式にする案は、zsh 専用構文のままでは成立しない。関数の
  書き換えが要り、その書き換えが上の静かな差異を呼び込む。`test_helper.bash` のコメントが
  ガード方式を勧めているのは bash スクリプト (raycast toggle) についてであり、前提が違う

### 副次的に見えている穴

`.zshrc` は静的検査を一切受けていない。pre-commit の shellcheck hook は `files: \.sh$`
で対象を絞っており、仮に対象へ含めても shellcheck は zsh を解析しない (0.11.0 で実測、
SC1071 でエラー終了する)。現状 zsh 構文の検査は手で `zsh -n` を回したときだけ働く。

これは `zsh -n` を呼ぶ 1 行の hook で塞げるので、下のタスクのうち他の項目と依存関係が無く
単独で完了できる。テスト方式の決着を待つ必要はない。
