# improve: issue-id.py の接頭辞と走査の除外を外から渡せるようにする

## 背景

in-repo-issue skill に同梱の `issue-id.py` (canonical は agentic-coding-tools) は、識別子の接頭辞を `PREFIX = "ISSUE-"` と決め打ちしている。旧記法 (`<N>_<title>`、接頭辞なし) で大量の Issue を運用していて移行の予定が無いリポジトリでは、そのまま使うと次のことが起きる (2026-10-08 の報告)。

- `--check` が全 Issue ぶんのディレクトリ名の違反を返し、本来見たい数字記法の違反が埋もれる
- `--check-diff` が、Issue を足す PR を毎回ディレクトリ名の違反で赤にする
- `--next` が接頭辞つきの識別子を出すので、呼び出し側で番号だけを取り出している

報告元では、skill の版を byte 一致で写したうえで、ラッパーが importlib で読み込み、内部の名前 (`PREFIX` / `ISSUE_DIR` / `SKIP_SUFFIXES` / `_tracked_files`) を差し替えてから `main()` を呼んでいる。内部の名前に依存するので、上流で名前が変わると壊れる。`ANY_ISSUE_DIR` は読み込み時に `ISSUE-` から作られたままで、接頭辞を任意とする形なので、裸の数字にもたまたま一致している。

依頼は 3 つで、1 と 2 が両方そろって初めて報告元のラッパーを消せる。

1. 接頭辞を外から渡せるようにする (引数、環境変数、リポジトリ側の設定ファイルのいずれか)。`ISSUE_DIR` と `ANY_ISSUE_DIR` を、読み込み時ではなく呼び出し時に接頭辞から作る。接頭辞が空のときにディレクトリ名の規則が `<N>_<title>` になることをテストで固定する
2. `--check` に、走査から外すパスの集合を渡す口を作り、外した件数を要約に出す (「拡張子で除外 N」と同じ形)。closed の Issue や適用済みの migration のようなスナップショットは直さない方針のリポジトリでは、これが無いと `--check` が永久に緑にならず、`--check-diff` の backstop として CI に載せられない
3. `SKIP_SUFFIXES` に `.svg` を足すか検討する。`fill="#000"` のような色指定が数字記法として数えられる (css / scss を除外しているのと同じ理由)

あわせて報告された使い方の罠 (挙動は設計どおり。SKILL.md に書くかは判断する)。

- 違反は stderr に出る。stdout だけを読む呼び出し側では 0 件に化ける
- `--check-diff --base <ref>` はコミット済みの差分しか見ない。コミット前に回すときは `--base` を付けずに index を見る
