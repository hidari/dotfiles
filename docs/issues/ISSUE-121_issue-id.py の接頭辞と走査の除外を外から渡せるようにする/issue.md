# improve: issue-id.py の接頭辞と走査の除外を外から渡せるようにする

## 背景

in-repo-issue skill に同梱の `issue-id.py` (canonical は agentic-coding-tools) は、リポジトリごとに違ってよい方針をモジュールの定数として決め打ちしている。識別子の接頭辞 (`PREFIX = "ISSUE-"`)、走査の範囲、拡張子での除外 (`SKIP_SUFFIXES`) の 3 つである。旧記法 (`<N>_<title>`、接頭辞なし) で大量の Issue を運用していて移行の予定が無いリポジトリでは、そのまま使うと次のことが起きる (2026-10-08 の報告)。

- `--check` が全 Issue ぶんのディレクトリ名の違反を返し、本来見たい数字記法の違反が埋もれる
- `--check-diff` が、Issue を足す PR を毎回ディレクトリ名の違反で赤にする
- `--next` が接頭辞つきの識別子を出すので、呼び出し側で番号だけを取り出している

報告元では、skill の版を byte 一致で写したうえで、ラッパーが importlib で読み込み、内部の名前 (`PREFIX` / `ISSUE_DIR` / `SKIP_SUFFIXES` / `_tracked_files`) を差し替えてから `main()` を呼んでいる。内部の名前に依存するので、上流で名前が変わると壊れる。

接頭辞に依存するのは `ISSUE_DIR` と、違反や採番の出力に接頭辞を埋め込む文字列だけである。`ANY_ISSUE_DIR` は接頭辞を任意にして旧記法も同じ番号空間で数える設計なので、接頭辞が空でも今と同じものに当たる。

外から渡す口は、引数や環境変数ではなくリポジトリ側の設定ファイル 1 つにまとめるのがよい。呼び出し元は skill 自身の採番、CI の `--check` / `--check-diff`、pre-commit と複数あり、引数や環境変数では同じ値を呼び出し元ごとに繰り返すことになって、ラッパーが散らばった引数として戻ってくる。設定の置き場は、agentic-coding-tools の ISSUE-63 の候補 2 (GitHub 記法の免除をプロジェクト側の設定で与える) と同じ問いなので、一緒に決める。
