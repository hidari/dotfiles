# refactor: メモリのファイル名と name を kebab へ統一する

## 背景

ISSUE-49 でメモリを共有したときに切り出した。共有そのものは命名が揃っていなくても成立するので、
統合では命名に手を入れていない。

canonical はファイル名の stem を kebab 化したもので、frontmatter の `name` も同じ値へ揃える、
という規約は 2026-08-24 の移行時に確定している。規約に従っているのは手で移行した 3 プロジェクト
(dotfiles / scriptoria / miterude) だけで、残りは移行前の命名のまま残っている。

`[[...]]` 記法は `name` を指すので、`name` がファイル名からずれていると参照が解決しない。

## 実測 (2026-08-27、統合後の実体で計測)

| 項目 | 件数 |
| --- | --- |
| メモリ総数 (索引含む) | 689 |
| ファイル名にアンダースコアを含む | 393 |
| `name` が stem と一致しない | 249 / 666 |
| `[[...]]` の総数 | 1111 |
| うち解決しない参照 | 97 |

アンダースコア命名が残っているのは 7 プロジェクト。多い順に astralys-art 154 / relay 130 /
studio-Hamiltonian-logo-automation 87 / mock 9 / rip-zip 5 / spectoru 5 / tolove-ru 3。

解決しない 97 件の内訳は astralys-art 27 / studio-Hamiltonian-logo-automation 25 /
scriptoria 16 / dotfiles 13 / relay 11 / canbright-miterude 3 / その他 2。

## 着手前に確認すること

- 解決しない 97 件には 2 つの原因が混ざっている。命名のずれで解決しないものと、存在しない
  メモリを指しているもの。後者は仕様上許容されるので、直す対象は前者だけになる。着手前に
  切り分けること。切り分けずに件数を成果指標にすると、直せない分を追いかけることになる
- 三点を同時に揃える必要がある。ファイル名の stem、frontmatter の `name`、参照側の `[[...]]`。
  どれか一つでも欠けると参照が解決しない。`MEMORY.md` の相対リンクも同じ
- 実体は `~/.claude-shared/projects/` の 1 箇所なので、直せば両アカウントへ同時に反映される。
  逆に壊した場合も両方へ波及する
