# fix: Brewfile の射程が散文どうしで食い違い実機とずれている

## 背景

Brewfile が何を宣言すべきかについて、リポジトリ内の散文が 2 通りのことを言っている。

- `bootstrap.sh` は Brewfile を「brew 依存の single source of truth」と書いている
- `config_guard.tool_provisioning` の docstring は検査の射程を「リポジトリの検査とテストを回す
  ために要るコマンドだけ」と明記し、個人の作業で使うコマンドは要求側に入らないと述べている

**この 2 つは矛盾しない。**前者は Brewfile の射程、後者は検査の射程で、対象が違う。「検査が
要求しない」は「Brewfile に載らなくてよい」を含意せず、SSOT の Brewfile をその部分集合だけ
検査する構成は成立する。

**食い違っているのは散文どうしではなく、`bootstrap.sh` の宣言と実態である。**下の実測のとおり
実機の brew 依存は Brewfile に全ては載っていない。single source of truth を名乗る側が実態から
外れているので、宣言を実態へ寄せるか、宣言の射程を狭めるかを決める必要がある。

## 実測 (2026-09-16 時点のスナップショット)

宣言 formula 34 / cask 6 に対し、実機は formula 59 (`brew leaves --installed-on-request`) /
cask 12。**宣言から漏れているのは formula 26 / cask 6。**

重いのは `bootstrap.sh` の `SYMLINK_PAIRS` が設定を配る 4 件が漏れていること。herdr / neovim /
ghostty / raycast はいずれも Brewfile に無いので、**fresh マシンでは「入っていないツールの設定
だけが置かれる」状態になる。**エラーにはならず、そのツールを使おうとして初めて気づく。

`google-cloud-sdk` は宣言済みの `gcloud-cli` と同じものを指す旧名の残骸に見えるが、確かめて
いない。

### 数え方 (着手時に数え直すときの規約)

件数は動くので、上の値はスナップショットとして扱うこと。数え直すときは次を守る。

**宣言側と実機側を同じ規約で正規化する。**Brewfile は `supabase/tap/supabase` のように tap 修飾で
書く行があり、`brew leaves` もフル修飾で返す。片側だけ最後のセグメントへ落とすと、**同じものが
「宣言漏れ」と「宣言にあるが実機に無い」の両方へ出る**偽の差分になる。

**この 2 つの誤りは別々に効く。**最初に数えたときは両方を同時に踏んで 32/8 になったが、原因の
寄与は次のように分かれる。正規化だけを直した人は 31/6 を得るので、どちらか一方の修正では
正しい値に着かない。

| 踏んだ誤り | 得られる値 |
| --- | --- |
| 正規化の片側適用のみ | 31 / 6 |
| 作業ブランチの古い Brewfile のみ | 27 / 8 |
| 両方 | 32 / 6 ではなく 32 / 8 |
| どちらも踏まない | 26 / 6 |

cask 側は tap 修飾を持つものが宣言にも実機にも 0 件なので、**6 から 8 への増分は 100% が古い
Brewfile を読んだことに由来する。**正規化の問題ではない。

**実機側は `brew leaves --installed-on-request` を使う。**`brew list` は依存として入ったものを
含むので、宣言すべきかどうかの判断材料にならない。

**作業ブランチの working tree を読まない。**別ブランチでマージ済みの変更が「宣言漏れ」として
出る。対象は `git show origin/main:home/.Brewfile` で取る。

## 決めること

- Brewfile の射程。全部を宣言する側へ寄せるか、検査とテストに要るものへ限る旨を `bootstrap.sh`
  の散文側で明記するか
- **射程を広げる場合、PUBLIC へ出せない名前をどう扱うか。**未宣言のものには、追跡下に 1 度も
  現れていない名前が複数含まれる。全部を宣言する分岐を採ると、それらを PUBLIC な追跡下ファイルへ
  書き出すことになり、このリポジトリの規範と正面からぶつかる。除外するなら除外の基準が要り、
  基準自体も追跡下に置くと同じ問題を持つ
- **`brew leaves` は明示導入したものでも、他の formula の依存になった時点で消える。**実測では
  `deno` が「宣言にあるのに実機に無い」側へ落ちた (実際には導入済み)。つまり 26 という値は
  構造的に**下限**で、断定形で書くと過小評価へ外れる
- 設定を配っている 4 件 (herdr / neovim / ghostty / raycast) の扱い。射程をどちらに決めても、
  「設定は配るが本体は入らない」状態を残すかどうかは別に決める必要がある
- 射程を決めた後、どちらの散文を直すか。両方に書くと同じ制約が 2 箇所へ散る
