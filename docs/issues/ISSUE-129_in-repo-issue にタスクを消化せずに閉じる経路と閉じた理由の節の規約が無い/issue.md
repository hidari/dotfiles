# feat: in-repo-issue にタスクを消化せずに閉じる経路と閉じた理由の節の規約が無い

## 背景

`dev-workflow:in-repo-issue` が閉じる経路として持つのは、`## タスク` を全部消化したとき (Phase C / D) と、子が全部 closed になったとき (Phase E) の 2 つだけである。タスクを消化しないまま閉じる判断を下したときに従う手順が無く、閉じた理由を本文のどこにどう書くかの規約も、skill とテンプレートのどちらにも無い。

他のリポジトリで in-repo Issue を棚卸ししたセッションから、受け箱経由で次の報告が届いた (2026-10-20)。閉じる判断が 3 つの形で出て、どれも上の 2 経路に当てはまらず手で組んだという。

- 子を外して親を閉じる: 親の子のうち 1 本だけが外の判断待ちで残り、親自身の作業は無かった。A.5 (分割) の逆にあたる操作で、親の `children` と子の `parent` の両方から外し、親の `## タスク` の該当行の扱いを決める必要があった。片側だけ外すと「closed の親を持つ open の子」になる
- 別の置き場へ移して閉じる: 着手の条件が揃っていない Issue を別の Issue のタスクへ吸収しようとしたが、着手条件のうち吸収先に結び付くのは一部だけで、吸収先を閉じると残りの見張りが消えると分かった。そのため、プロジェクトが条件待ちの事項を集めておく置き場へ移した。吸収と移動のどちらにするかの基準が無かった
- 見送りで閉じる: 作らないと決めた Issue を、理由を書いて閉じた。タスクは未チェックのまま残る

3 つとも閉じた理由を書く節が要り、報告元では `## クローズの理由` を立てて揃えた。最初の版では「背景」の末尾の段落と新しい節の 2 通りが同じ PR に混ざったという。

あわせて、子を外して親を閉じたときに、親が本文に持つ完了の定義からその子を外したのかがどこにも残らなかった。Phase E は子の所在だけで親の close を判定するので、完了の定義は判定に入らない。

## 確かめたこと (2026-10-20)

- skill (agentic-coding-tools の main、v0.18.0) の Phase は A〜F で、閉じるのは C / D と E だけ。F は reopen。テンプレートの節は 背景 / タスク / 関連 の 3 つで、閉じた理由の節は無い
- dotfiles の `closed/` にある Issue 55 件のうち 10 件が、未チェックのタスクを残したまま閉じている。どれも理由を書く節を持つが、書き方が 2 系統に割れている。`## クローズ理由 (<日付>)` を本文の先頭に置く形が 5 件 (Issue 3、14、24、ISSUE-103、ISSUE-105)、`## クローズの記録 (<日付>)` を `## タスク` の後に置く形が 5 件 (ISSUE-62、ISSUE-63、ISSUE-77、ISSUE-85、ISSUE-99)。報告にある揺れは dotfiles でも起きている
- agentic-coding-tools の `closed/` にある 40 件には、未チェックのタスクを残したものが無い
- agentic-coding-tools の `scripts/check-issue-closure.py` の不変条件 A が見るのは active な Issue だけなので、未チェックのまま `closed/` へ移した Issue は拒否されない。この検査は配布されておらず、dotfiles にも無い

## 報告者の提案 (未検証)

- 「タスクを消化せずに閉じる」経路を 1 つ定める。子を外す / 別の置き場へ移す / 見送る の 3 形を持ち、どれでも閉じた理由の節に理由と移した先の識別子 (あれば) を書く
- 子を外す操作では、両側の `parent` / `children` を外し、親の `## タスク` から該当行を消し (開いたままの子を `[x]` にしない)、親の完了の定義から外したかを書くことを手順にする。仕組みは要らず、手順に 1 行入れれば足りる
- 条件待ちの Issue の送り先 (吸収先の Issue へ寄せるか、プロジェクトの条件待ちの置き場へ移すか) を、着手条件が吸収先だけで決まるかどうかで分ける
- frontmatter の「これ以外は持たない」は変えず、本文の節の規約として足す

## タスク

- [ ] 消化せずに閉じる経路の形を決める。報告の 3 形で足りるか、dotfiles の 10 件の閉じ方を分類して確かめる
- [ ] 閉じた理由の節の名前と置き場所を 1 つに決め、テンプレートか skill のどちらが持つかを決める。dotfiles の既存の 2 系統を揃え直すかもあわせて決める
- [ ] 子を外す手順で、親の `## タスク` の行を消すか残すかを決める。Phase E が親の箱を判定に使わないことと、agentic-coding-tools の ISSUE-45 (不変条件 A が親の箱を判定に使う) の両方と矛盾しない形にする
- [ ] 決めた内容を agentic-coding-tools の skill へ入れる
