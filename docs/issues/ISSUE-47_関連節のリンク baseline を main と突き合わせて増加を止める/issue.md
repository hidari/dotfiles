# fix: 関連節のリンク baseline を main と突き合わせて増加を止める

## 背景

config-guard の `related_refs` は `## 関連` 節に残るローカルリンクの本数を `LINK_BASELINE` に
記録し、実態と突き合わせている。減った側は「baseline も下げること」として報告するので、
リンクを外したのに記録を残す形は止まる。

止まらないのは増える側。リンクを 1 本足して同じコミットで `LINK_BASELINE` を 1 増やすと、
実態と記録が一致するので違反 0 件の緑で通る。定数のコメントと Issue 43 の spec は
「単調非増加で運用する」と書いているが、それを守っているのはレビューであって検査ではない。

同じ形は `instruction_budget` で既に踏んでいる。超えたときに上限のほうを書き換えれば通る
状態は上限として働かず、実際に 2 度引き上げている。そこへ `budget_ratchet` を足して
`origin/main` の値と突き合わせるようにしたのが今の形。

## 決めること

`budget_ratchet` を一般化して 2 人目の利用者を作れるか。今は「追跡ファイルの module レベル
定数を `origin/main` から ast で読む」処理が予算専用に書かれている。一般化するなら
(モジュールパス, 定数名, 値の取り出し方) を引数にする形になる。

引き上げの記録は要らない見込み。予算は増える前提があったので `BUDGET_RAISES` を持つが、
こちらは規約が「新規はリンクを張らない」なので厳格な単調非増加で詰まらない。
