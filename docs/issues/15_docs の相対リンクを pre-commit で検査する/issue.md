# ci: docs の相対リンクを pre-commit で検査する

## 背景

Issue を `docs/issues/closed/` へ移すたびに、その Issue を指す相対リンクと、その Issue から出ているリンクの両方が切れる。`../10_...` と `../closed/10_...` の書き分けが両端の open / closed 状態に依存するためで、close する側とは別のファイルへ波及編集が要る。

これは仮説ではなく実績がある。`closed/9_.../issue.md` のリンクは導入コミットの時点で `../closed/7_...` (= `docs/issues/closed/closed/7_...`) と壊れており、main 上で壊れたまま残っていた。PR #77 のレビューで検出して直したが、検出したのは人間とレビューエージェントの目視である。

pre-commit には ruff / mypy / pytest / gitleaks / ast-grep / shellcheck が揃っているのに、Markdown の相対リンクを見るものが 1 つも無い。CLAUDE.md の「静的検査可能なルールはプロンプトではなく、その環境の linter か ast-grep で記述する」に真正面から該当する。

PR #77 の時点で、open な Issue を閉じたときに切れるリンクを実測してある。

| 閉じる Issue | 切れるリンクの本数 |
| --- | --- |
| #8 | 3 |
| #11 | 1 |
| #12 | 1 |

## タスク

- [ ] 検査の範囲を決める (`docs/` 配下のみか、README や CLAUDE.md も含むか。見出しアンカーまで見るか)
- [ ] リンク解決を検査するスクリプトを書く。URL エンコード (`%20`) のデコードが要る
- [ ] 仕様をテストで表現する (切れたリンクを検出すること、生きたリンクを誤検出しないこと、アンカー付きリンクの扱い)
- [ ] pre-commit と CI に配線する
- [ ] Issue を close したときの波及編集を減らせないか併せて検討する (リンク形を open / closed に依存しない形にできるか)
