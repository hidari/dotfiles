# chore: private リポジトリ G の CI で pre-commit 設定の構文を検査する

## 背景

ISSUE-86 の展開で、テストを回す CI を持つリポジトリには `.pre-commit-config.yaml` が壊れたら CI が赤くなる検査を足すと決めた (ユーザー決定 2026-10-22)。設定が壊れると pre-commit が起動せず、漏洩検査の hook が黙って走らなくなるため。

private リポジトリ G だけはその検査を入れずに展開を終えた (ユーザー決定 2026-10-22 で切り出し)。G の CI には、コマンドの入口と道具の版の置き場、設定ファイルだけを変えた PR で走る job の決まり方について独自の作法があり、それに沿って入れると変更が小さく収まらないため。作法の中身は G の側の文書が持つ。

## タスク

- [ ] G の作法に沿って、pre-commit の版を固定して CI で入れる
- [ ] `pre-commit validate-config .pre-commit-config.yaml` を G の作法の入口から呼ぶ。引数なしの validate-config は何も検査せず rc 0 を返すので、ファイルを渡す
- [ ] 設定ファイルだけを変えた PR でもその検査が走るよう、CI の起動条件を合わせる
- [ ] G の CI の文書を合わせる
- [ ] 壊した設定で CI が赤くなることを一度確かめる

- ISSUE-64: 取り付けの形を確立した
