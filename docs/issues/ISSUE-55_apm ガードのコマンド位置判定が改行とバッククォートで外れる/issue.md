# fix(hooks): apm ガードのコマンド位置判定が改行とバッククォートで外れる

## 背景

`home/.claude/hooks/apm-install-guard.py` は、ツリーが汚れている状態での `apm install` を
止めるガードである。判定は「トークン列の中で `apm` がコマンド語の位置にあるか」で行う。

この位置判定が 5 つの形で外れる。使い捨ての dirty リポジトリでフックそのものを走らせて確認した。
対照 4 件が期待どおりに振る舞っているので、ガード自体は生きている。

| 入力 | tokenize の結果 | フックの判定 |
| --- | --- | --- |
| `apm install` (対照) | | deny |
| `apm install; git status` (対照) | | deny |
| `echo "apm install"` (対照) | | 素通り (正しい) |
| `apm view` (対照) | | 素通り (readonly なので正しい) |
| `echo hi` + 改行 + `apm install` | `['echo', 'hi', 'apm', 'install']` | 素通り |
| `echo hi` + CR + `apm install` | `['echo', 'hi', 'apm', 'install']` | 素通り |
| `` echo `apm install` `` | ``['echo', '`apm', 'install`']`` | 素通り |
| `bash -c 'apm install'` | `['bash', '-c', 'apm install']` | 素通り |
| `sh -c 'apm install'` | `['sh', '-c', 'apm install']` | 素通り |

### 機序

`is_command_position` は「直前のトークンが演算子ならコマンド位置」と判定する。演算子の判定は
`_PUNCTUATION_CHARS` に列挙した文字だけで構成されたトークンかどうかで行う。

ここに改行と CR が入っていない。改行は shlex にとって単なる空白なのでトークンにならず、
`apm` の直前には `hi` という普通の語が残る。結果としてコマンド位置ではないと判定される。
先頭が改行の場合 (`\napm install`) だけは前にトークンが無いので deny になり、機序と一致する。

バッククォートも同じく列挙に無いため語へ密着し、`` `apm `` という 1 トークンになる。
`sh -c` 系はクォート内が 1 トークンにまとまり、中身が走査対象から外れる。

この形はもともと「`shlex.split` はシェル演算子を切らない」という欠陥を
`punctuation_chars=True` で塞いだ結果である。塞ぎ方が「演算子を文字の集合で定義する」形
だったため、文字ではない区切り (改行・CR) と、punctuation に含まれない記号
(バッククォート) が漏れた。

### 実害の範囲

このガードは security guard ではなく事故防止で、`apm install` が deploy 先を上書きして
未コミットの変更を消すのを止めるためにある。すり抜けても壊れるのは自分の作業ツリーで、
権限昇格や情報漏洩には繋がらない。

ただし「ガードがある」という前提で手順を組むと、すり抜ける形を踏んだときに前提が崩れる。
特に改行区切りは複数行のコマンドを 1 回の Bash 呼び出しで流すときに自然に発生する。
