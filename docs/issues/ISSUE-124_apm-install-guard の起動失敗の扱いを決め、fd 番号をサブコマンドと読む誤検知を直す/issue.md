# fix(hooks): apm-install-guard の起動失敗の扱いを決め、fd 番号をサブコマンドと読む誤検知を直す

## 背景

2026-10-19の棚卸しで、PreToolUse の `apm-install-guard.py` について2つ見つかった。

### 起動に失敗したときに素通りする

スクリプトは解釈できない入力を deny へ倒すが、スクリプト自体が起動できないとき (ファイルが無い、python3 が落ちる、タイムアウト、出力が JSON でない) は、hook の既定の `onFailure: continue` で Bash の呼び出しがそのまま通る。`home/.claude/settings.json` のこの hook は `onFailure` を持たない。インストール済みの 2.1.303 のバイナリは `continue` と `block` の2値を持つ。

`block` にすると、hook が直るまで Bash の呼び出しがすべて止まる。一方で、dirty な木での `apm install` は exec 時の shim (`scripts/apm-guard/`、ISSUE-55 で判定点を移した) も止めるので、hook が起動できなくても shim が PATH にあれば防御は残る。shim が PATH に居ないことは guard-health のプローブが告げる (ISSUE-59)。この hook が最後の1層ではないことを踏まえて決める。

2026-11-10の仕分けで、別のリポジトリから同じ機序の報告が届いた。PreToolUse の hook は、時間切れ・起動の失敗・0と2以外の終了で、既定では止めずに素通りさせる。`onFailure: "block"` を付けると止まる (Claude Code 2.1.295以降)。初回の起動で uv が Python を取りに行くと18秒かかり、10秒の timeout を超えた (実測とドキュメント)。起動の失敗が実際に起きる経路の実例として、`block` を付けるかの判断の材料になる。

### fd 番号をサブコマンドと読む

作業ツリーが dirty なとき、読むだけのコマンドが deny される。hook に JSON を直接渡して再現した。

| コマンド | 判定 |
| --- | --- |
| `apm --version` | 通る |
| `apm list` | 通る |
| `apm --version 2>/dev/null` | deny (「apm 2 は deploy 先を上書きし」) |
| `apm --version 2>&1` | deny |

リダイレクトの fd 番号 `2` を、`apm` に続く語として読んでいる。演算子を切る分割では `2>` が `2` と `>` に分かれ、`2` が普通の語として残るためと見ている (未確認)。deny に倒れる向きなので安全側ではあるが、作業中はツリーが dirty なことが多く、その間 apm の読み取りに出力の抑止を付けられない。

### ヘルプの呼び出しとコマンドの中の cd

2026-11-10の仕分けで、別のリポジトリから、読むだけの呼び出しを止める別の形の報告が届いた。apm-install-guard は `apm install --help` でも、`cd` で git の外へ出ても止める。判定に使う cwd は hook の入力のもので、コマンドの中の cd ではない (実測)。fd 番号の誤読と同じく deny に倒れる向きで、dotfiles では確かめていない。

- 2026-11-26の仕分けで、別のリポジトリから、コードの中の語で止まる別の形の報告が届いた (届いたのは2026-11-24)。apm を名指しで止める PreToolUse の hook は、Bash のコマンド文字列に含まれる「apm =」のような Python の変数名でも発火した。照合のスクリプトはファイルに書いて呼ぶと通る (実測)。報告者の提案: apm-install-guard の hook の照合を、コマンドの先頭の語 (apm) だけに絞れないか検討する (実測)。dotfiles で確かめたこと (2026-11-26、main の 17d475f): `home/.claude/hooks/apm-install-guard.py` は、293行目で `apm` がコマンド語の位置 (244行目の `is_command_position`) にあるときだけ判定する。228行目の `tokenize` は、クォートした文字列を1つのトークンのまま残す。提案の向きの位置の判定は既にある。報告元のコマンドの形が原文に無いので、「apm =」がどの形でコマンド語の位置に来たのかは分からない。報告元の hook が dotfiles の main と同じ版かも分からない。実験はしていない。仕分けたセッションの解釈: 上の fd 番号の誤読やヘルプの呼び出しと同じく、deny に倒れる向きの誤検知。照合を絞る直しは、ISSUE-55 で判定点を exec 時の shim へ移した二層の中で hook の射程を狭める変更になる。直すなら fd 番号の表と同じく、止めるべき形と通すべき形を pin してから決める
