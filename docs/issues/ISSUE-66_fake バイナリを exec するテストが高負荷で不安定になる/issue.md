# test(hooks): fake バイナリを exec するテストが高負荷で不安定になる

## 背景

ISSUE-59 の作業中、claude-hooks のテストが同一コミットに対して緑と赤を行き来した。
2026-08-31 に 3 回観測している。いずれも並列 subagent を 6 本走らせている最中で、
負荷が落ち着くと同じコミットが安定して緑になる。

赤くなったのは次の 2 件で、どちらも fake の tirith スクリプトを一時ディレクトリへ書いて
実行するテストである。

| テスト | ファイル | 由来 |
| --- | --- | --- |
| `test_tirith_が_clean_へ応答すれば健全` | `scripts/claude-hooks/tests/test_guard_probes.py` | ISSUE-59 で追加 |
| `test_clean_command_allows_silently` | `scripts/claude-hooks/tests/test_tirith_hook.py` | 既存 (main から変更なし) |

失敗時の文面は `tirith: check timed out — blocked for safety` で、壁時計のタイムアウトに
当たっている。`probe_tirith` の上限は 5 秒、tirith-check.py 側は既定 10 秒である。
即座に終了する fake スクリプトがこの上限を超えるのは、実行そのものではなく起動が遅れている
ことを意味する。

## 機序の見立て (未確定)

失敗した時間帯に `ps` を取ったところ `syspolicyd` が CPU 83.8% を占めていた。macOS が
実行ファイルの署名・ポリシーを評価するデーモンで、**新規に作成された実行ファイルを exec
するたびに評価が走る**。これらのテストはテストごとに新しいスクリプトを書いて実行するため、
評価の対象が毎回「初見のファイル」になる。

この見立てはまだ相関でしかない。同時刻に無関係な cargo のビルドも走っており、
`syspolicyd` の負荷をテストへ帰属させる対照実験はしていない。**着手時には機序の確定から
始めること。** 見立てが外れていると、手当ての方向 (fake の作り方を変える) ごと外れる。

## 実害の範囲

- CI で観測されたことは無い。CI は subagent を並列で走らせないので、同じ負荷はかからない
- ローカルでは、この repo の品質ゲートが並列レビューを既定にしているため、**今後も同じ状況が
  繰り返し起きる**。マージ直前の検証で赤が出ると、原因がコードか環境かをログまで読まないと
  判別できない

## タスク

- [ ] 機序を確定させる。fake スクリプトの exec 遅延が原因かを、負荷を制御した対照で確かめる。
      相関で手当てを決めない
- [ ] 手当ての候補を比較する。fake をテストごとに作り直さない形 (1 本を使い回して振る舞いを
      env で切り替える) と、テスト時だけ上限を延ばす形の 2 つが候補になる。後者は
      「テストのために本番に無い経路を作る」側へ倒れるので、採るなら理由を残す
- [ ] タイムアウトの上限そのものを検査するテスト (`TIRITH_TIMEOUT` の 3 件) は、上限を延ばす
      手当てを採ると意味が変わる。どちらの手当てでもこの 3 件が守っている性質が残ることを
      確認する
