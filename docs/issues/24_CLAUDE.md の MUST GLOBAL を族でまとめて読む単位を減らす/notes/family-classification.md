# CLAUDE.md 族分類 草案 (2026-08-17)

Issue #24 のタスク 2 から 6 に対する草案。

ID の採番規約: `home/.claude/CLAUDE.md` を上から読み、コードフェンス内を除いて
`- ` または `N. ` で始まる行をトップレベル項目とする。直前の見出しの出現順を `H<番号>`、
その見出し配下の連番を 2 桁で付けて `H<番号>-<連番>` とする。番号はゼロ始まりで、
前文が `H0`、最初の `##` 見出しが `H1` になる。2026-08-17 時点の 314 行に対して 94 項目。

コードフェンスを除く点が要る。除かないとコミットメッセージ例の中の `- CSS Modules ...` を
項目として数えてしまう。番号付きリストを含める点も要る。含めないと作業プロトコルの
4 項目が落ちる。当初 92 と数えたのはこの 2 つの誤りが相殺した結果だった。

材料は次の 2 つの実測で、同じディレクトリに置いてある。

- `cross-reference-census.json`: 項目間の相互参照 47 件 (分割で壊れるもの 28 件)
- `load-mechanism-triage.json`: 94 項目の scopable / nature 判定

このファイルが長い理由はルールの数ではなく、各ルールが自分の根拠を抱えていること。
削減の主経路は規範と知識の切り分けであり、paths によるスコープは従になる。
両者は排他ではなく、H6-05 のように双方に該当する項目では二重に効く。

## 採る構成

三層に分ける。

1. CLAUDE.md 本体には核だけを残す。文書自身の語彙定義と、他のどの族にも属さない前提。
2. 族ごとの規範を rules へ置く。原則を 1 行、その下に具体的な指示。
3. 族ごとの知識を skill へ置く。実測事例、再現条件、機構の説明。

知識を skill へ移すことは削除ではない。実測値と再現条件は境界を判断する材料として要るため、
消さずに引ける場所へ移す。常時ロードから外れるだけで、必要な場面では読める。
