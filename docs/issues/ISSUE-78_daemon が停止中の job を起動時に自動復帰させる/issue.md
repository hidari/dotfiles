# docs(claude): daemon が停止中の job を起動時に自動復帰させる

## 背景

2026-09-06 に、このリポジトリで Claude Code を起動したのに別プロジェクトのセッションが
画面に出るという取り違えが起きた。その調査で、背景にある daemon の挙動が実測で確定した。

daemon はマシン上で設定ディレクトリ単位に 1 つ存在する。作業ディレクトリ単位ではない。
実体は `/tmp/cc-daemon-<uid>/<hash>/` で、`<hash>` は設定ディレクトリの絶対パスの
sha256 先頭 8 桁である (2026-09-06 に自分で計算して照合し、一致を確認した)。

この daemon は起動時に、レジストリ (`<設定ディレクトリ>/daemon/roster.json`) に残っている
job を自動的に復帰させる。ログには `bg claimed-spare <id> (fleet)` として現れる。
括弧の中は起動主体で、3 種を観測している。

| 括弧の値 | 起動主体 |
| --- | --- |
| `spare` | 対話セッションの新規起動 (ユーザーの操作) |
| `fleet` | daemon によるレジストリ job の自動復帰 (ユーザーの操作ではない) |
| `slash` | スラッシュコマンドによる job 作成 |

同時刻に存在した 3 つの worker を roster から読むと、区別がはっきりする。

| worker | 作業ディレクトリ | source | mode |
| --- | --- | --- | --- |
| 起動した対話セッション | このリポジトリ | spare | prompt |
| 待機中の spare | このリポジトリ | spare | prompt |
| 2 日前のセッション | 別プロジェクト | fleet | resume |

`fleet` のエントリは `mode: resume` と transcript のパスを持ち、過去のセッションを
会話ごと再開する形になっている。

## 何が問題か

あるプロジェクトで Claude Code を起動しただけで、無関係なプロジェクトの停止中 job が
走り始める。ユーザーの操作は介在しない。

復帰した job が完了状態のまま残ると、次回以降の起動画面が一覧画面になる。このとき
一覧に出ている job を「自分が意図して起動したもの」と読むと誤る。起動理由はログの
括弧でしか判定できない。

## このリポジトリで手が届く範囲

届かない。daemon の挙動は Claude Code 本体の設計で、設定キーによる抑止は
`disableAgentView` しか見つかっていない (本体バイナリ 2.1.263 に文字列として存在する
ことは確認済み)。ただしこれは一覧画面ごと無効化するので、background session を使う
運用とは両立しない。

現実的な対処は、不要になった job をレジストリから落とすことである。
