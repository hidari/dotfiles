# セキュリティの一次実測

`~/.claude/CLAUDE.md` の「攻撃者が使える面を最小に保ち防御を 1 層に頼らない」カテゴリが持つ規範の、手当ての詳細と一次実測。

規範の遵守そのものには要らない。手当ての具体が要るとき、規範を疑うとき、似た失敗を踏んで「これは既知か」を確かめるときに読む。

## charset 検証を名前空間の検証と兼用した事故

設定ファイルの行を `^\.[A-Za-z0-9._-]+$` で検証して eval へ流していた。

- `.git` は関数 `git` を生やして外部コマンドを shadow した
- `.claude-dev` は静的定義のランチャを潰した

どちらも charset を通っていて、警告も出なかった。

接頭辞を固定し、派生に使う接尾辞を予約することで塞いだ。

逆向きの兼用もある。Make の `$(filter prefix_%,$(VAR))` で名前空間を検査すると、filter は値を空白で語に切って語ごとに照合するので、空白を含む値 (`prefix_a other`) が通る。名前空間の検査とは別に、文字種の検査を置く (実測)。

詳細は `~/.claude/references/delegation.md` の「subagent への制約伝達」。

## 多層防御の層の入力の出所

下の層の判定に渡す値を組むとき、判定に入る値がそれぞれどこから来るかを層ごとに辿る。「層がある」ことを確かめるレビューでは見つからない。テナントの一致を判定する下の層へ渡す2つのラベルを同じ値から組んでいたので、判定は恒真になり層として効いていなかった (実測)。

## 検査・置換と切り詰めの順序

長さの検査・切り詰めと、正規化・秘密の置換をどの順に置くかで、次の2つを踏む。

- 長さの検査より前に全文へ走る正規化 (置換) を足すと、それまで有界だった入力に無界の処理が入る (実測)。正規化を検査より前に置く変更のレビューでは、正規表現の後戻りの計算量を確かめる
- 外部コマンドの失敗の理由を下の層で長さの上限で切り、秘密の値を上の層 (呼び出し元) で置き換える構成では、秘密が切れ目をまたぐと前半だけが置き換わらずに残る。置き換えは切る前、つまり切る層と同じかそれより下で行う (推測。コードを読んで順序を確かめただけで、またがる入力での再現はしていない。この経路ではまたがらないので、直さずに見送った)

## 見えない文字と書式文字

外から来た値を端末へ出すとき、またソースや入力の中の見えない文字を拒否する集合を作るときに踏む。

制御文字だけを置き換えても、Unicode の書式文字 (bidi の上書き、ゼロ幅、BOM) が残ると、行の並びを入れ替えられたり、別の値が同じ見た目になったりする。Unicode プロパティの Cc と Cf を1本の正規表現で当てると両方を覆えた。テストで改行を剥いでから検査すると、改行の漏れを見逃す (実測)。

拒否する集合は文字の列挙ではなく Unicode の性質で作る。列挙はレビューのたびに穴 (タグ文字、異体字セレクタ、クメール文字の母音記号など) が見つかった (実測)。

- ソースの検査は Default_Ignorable_Code_Point (JS の正規表現なら u フラグで `\p{...}`) に、その集合に入らない U+2028・U+2029・U+FFF9〜FFFB を足す形が漏れにくかった。入れる前に、追跡下のテキストで一致が0件であることを確かめた (実測)
- 性質に寄せたあとで外の書式制御を1件だけ名指しで足したら、同じ理由が当てはまる Cf の文字が29個残っていた。名指しの例外を1件でも足したら、その理由が当てはまる一般カテゴリ全体を数え、基準を一般カテゴリと性質の和 (Cc・Zl・Zp・Cf・DI) から通すものだけを引く形にする (実測)
- 書記素の結合子 U+034F を文字クラスに直接入れると、Biome の noMisleadingCharacterClass が止める (実測)
