# 前提の背景

`~/.claude/CLAUDE.md` の「語彙と前提」カテゴリが持つ規範の、そう決めた理由。

規範の遵守そのものには要らない。方針を疑うとき、別の選択肢と比べるときに読む。

## library-contract パターンで切り離す理由

外部ライブラリを直接使わずアダプタ層で包むのは次の 5 点による。

- 外部ライブラリのバージョンアップ時の挙動確認テスト (契約テスト) を行いやすくする
- 外部ライブラリを差し替え可能にすることで、メンテナンスされなくなった場合の移行を簡単にする
- サプライチェーン攻撃の影響範囲をアダプター層に限定し、コアドメインロジックを保護する
- テスト時に Fake / Mock 実装へ差し替えて高速なユニットテストを可能にする
- コアドメインロジックを外部ライブラリの API 破壊的変更から隔離する

## 書かずに済ませることを模索する理由

現状の Claude が作るコードは不必要に複雑なコード・テスト・ドキュメントを書きがちで、
そのぶん drift しやすい。

書かないことでそもそも drift する面を減らせる。
特にコメントとテストコードは drift しやすく、しかも気づきづらい。

## テストコードをファーストクラスドキュメントとして書く理由

プロダクトコードとテストコードが the single source of truth になっていれば、
別途ドキュメントを保つ必要がなくなり drift の面が減る。

テストコードはリグレッションテストであると同時に仕様の記述でもある。
具体的な記述は各プロジェクト内の他のテストコードを参考にして一貫性を持たせる。
