# canonical を 1 つに決める話の一次実測

`~/.claude/CLAUDE.md` の「同じ制約を 2 箇所に書かず canonical を 1 つ決める」カテゴリと、`~/.claude/rules/testing-practices.md` の regex text-parse の項の、手当ての詳細と一次実測。

規範の遵守そのものには要らない。手当ての具体が要るとき、規範を疑うとき、似た失敗を踏んで「これは既知か」を確かめるときに読む。

## ディレクトリ構成ツリーを載せない

新規参入者の orientation はトップレベルの役割を示す簡潔な説明で足りる。

## 機械検証可能な制約の二重記述

seed_id の charset を schema `{1,128}` と指示文 `+$` に二重記述して上限が drift し、長い入力で全体が reject される回帰を埋め込んだ。

二重記述を残すしかない写しは、canonical と一致することを検査で守る。その検査にも黙って緑になる形がある。

- 走査の母集団を canonical の今の値から決めると、値を移した瞬間に古い値が母集団から外れ、写しに古い値が残っても緑になる。母集団は値ではなく形 (ファイルの種類や記法) で決め、移す前の値は禁止の定数として持つ。変異には「対照の外のファイルに古い値を1つ残す」を入れる
- 1対1の写しは、正典と等しいことだけで縛る。mise.toml の node の exact pin を、package.json の `engines.node` の下限と同じ版であることをテストで縛ると、下限だけを上げて写しを置き去りにする変異が赤になった (実測)

## regex での text-parse が生む phantom entry

bootstrap の `SYMLINK_PAIRS` を sed で parse し、配列内コメントを phantom source と誤読しかけた。

これは「機械検証可能な制約を schema と散文の両方に literal で書かない」の一種。

## 散文を参照へ書き換えたあとの検算

二重管理を消す作業がそのまま同型の欠陥を作る。しかも散文の真偽はどの検査も見ないので、CLAUDE.md が挙げる検算がどれも緑で通る可能性がある。

過去に次の失敗を踏んだ。

- 圧縮で列挙を親規範へ引き上げたところ、射程が「直前の数例」から「族全体」へ広がり網羅の主張に化けた
- カテゴリの既定強度がラベル無しの項目に効くため、2 項目を 1 項目へ統合したときに片方の強度が静かに降格した。識別子ベースの検算では出ず、強度ラベルを突き合わせる検算を別に書いて初めて検出した
- 重複を消すために2つの実測を1つの文へ畳んだら、どの日にどの値を読んだか、どの変更より前かが落ち、範囲も広がった。範囲の広がりは CLAUDE.md の4点の3点目で見えるが、日付・値・前後関係の欠落はどの点にも当たらない。散文を参照へ畳む修正は、それ自体が次のレビューの所見を生む (実測)

実測を畳んだときは4点に加えて、畳む前の文と並べ、日付・値・前後関係がそれぞれ残っているかを突き合わせる。
