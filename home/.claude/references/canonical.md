# canonical を 1 つに決める話の一次実測

`~/.claude/CLAUDE.md` の「同じ制約を 2 箇所に書かず canonical を 1 つ決める」
カテゴリが持つ規範の、手当ての詳細と一次実測。

規範の遵守そのものには要らない。手当ての具体が要るとき、規範を疑うとき、
似た失敗を踏んで「これは既知か」を確かめるときに読む。

## ディレクトリ構成ツリーを載せない

経験上必ず drift する。新規参入者の orientation は
トップレベルの役割を示す簡潔な説明で足りる。

rot した既存ツリーは更新ではなくセクションごと削除を優先する。

## 機械検証可能な制約の二重記述

同一制約の二重記述は CI が捕捉できない形で drift する。

seed_id の charset を schema `{1,128}` と指示文 `+$` に二重記述して上限が drift し、
長い入力で全体が reject される回帰を埋め込んだ。

## regex での text-parse が生む phantom entry

regex parse はその言語のパーサが無視する要素 (コメント等) を誤読して phantom entry を生み、
区切り・分割規約をテスト側に二重実装して drift させる。

bootstrap の `SYMLINK_PAIRS` を sed で parse し、
配列内コメントを phantom source と誤読しかけた。

これは「機械検証可能な制約を schema と散文の両方に literal で書かない」の一種。

## 散文を参照へ書き換えたあとの検算

二重管理を消す作業がそのまま同型の欠陥を作る。しかも散文の真偽はどの検査も見ないので、
4 つとも緑で通る可能性がある。

実際にこの移設作業で次の失敗を踏んだ。

- 圧縮で列挙を親規範へ引き上げたところ、射程が「直前の数例」から「族全体」へ広がり
  網羅の主張に化けた
- カテゴリの既定強度がラベル無しの項目に効くため、2 項目を 1 項目へ統合したときに
  片方の強度が静かに降格した。識別子ベースの検算では出ず、
  強度ラベルを突き合わせる検算を別に書いて初めて検出した
