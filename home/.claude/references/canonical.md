# canonical を 1 つに決める話の一次実測

`~/.claude/CLAUDE.md` の「同じ制約を 2 箇所に書かず canonical を 1 つ決める」カテゴリと、`~/.claude/rules/testing-practices.md` の regex text-parse の項の、手当ての詳細と一次実測。

規範の遵守そのものには要らない。手当ての具体が要るとき、規範を疑うとき、似た失敗を踏んで「これは既知か」を確かめるときに読む。規範の文面はここに再掲しない。

## ディレクトリ構成ツリーを載せない

新規参入者の orientation はトップレベルの役割を示す簡潔な説明で足りる。

## 機械検証可能な制約の二重記述

seed_id の charset を schema `{1,128}` と指示文 `+$` に二重記述して上限が drift し、長い入力で全体が reject される回帰を埋め込んだ。

## regex での text-parse が生む phantom entry

bootstrap の `SYMLINK_PAIRS` を sed で parse し、配列内コメントを phantom source と誤読しかけた。

これは「機械検証可能な制約を schema と散文の両方に literal で書かない」の一種。

## 散文を参照へ書き換えたあとの検算

二重管理を消す作業がそのまま同型の欠陥を作る。しかも散文の真偽はどの検査も見ないので、CLAUDE.md が挙げる4点の検算がどれも緑で通る可能性がある。

過去に次の失敗を踏んだ。

- 圧縮で列挙を親規範へ引き上げたところ、射程が「直前の数例」から「族全体」へ広がり網羅の主張に化けた
- カテゴリの既定強度がラベル無しの項目に効くため、2 項目を 1 項目へ統合したときに片方の強度が静かに降格した。識別子ベースの検算では出ず、強度ラベルを突き合わせる検算を別に書いて初めて検出した
