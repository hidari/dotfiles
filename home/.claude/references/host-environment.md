# ホスト環境とスクラッチ置き場の一次実測

`~/.claude/CLAUDE.md` の「自分の作業でホスト環境を壊さない」カテゴリが持つ規範の、手当ての詳細と一次実測。

規範の遵守そのものには要らない。手当ての具体が要るとき、規範を疑うとき、似た失敗を踏んで「これは既知か」を確かめるときに読む。

## ホストでの大規模処理

fontTools の `TTCollection` で巨大な合体 TTC (Sarasa SuperTTC) を非 lazy 展開してメモリが 52GB まで暴走し、macOS を OOM で巻き添えに落とした。
無音を「ハング」と誤診して放置したのが増悪要因だった。

macOS の `ulimit -v` は address-space 制限が信頼できず、上限として当てにできない。
隔離先のコンテナには OrbStack か Docker を使う。

## Tirith の削除検知と .cache

除外集合の中で `.cache` はビルド成果物として扱われている。
除外集合は tirith 側にハードコードされ設定から拡張できないので、こちらが名前を合わせる。
scratch は「まとめて消えて当然のもの」なので意味的にも正しい。

閾値は `tirith explain --rule mass_file_deletion` で確認する。

### explain の文面で判定しない

explain が挙げる除外例は `node_modules` / `target` / `dist` だけで、これを読んで「`.cache` は除外されない」と書き換えるコミットが実際に作られた。

0.3.3 で対照付きに実測すると、`.cache` 配下は深さ 1 でも 2 でも `rm` と `rm -rf` の双方が通り、`.cache` 外の同じ操作は CRITICAL で Block された。

対照を取らずに片側だけを見ると、ブロックされなかったことを「まだ発火していないだけ」と読むことも、ブロックを別ルールの発火と取り違えることもできてしまう。
「報告・前提を検証済みの網羅的事実として扱わない」と同じで、canonical を名乗る出力でも網羅とは限らない。

### 除外が効くのはコマンド文字列に現れる場合だけ

`cd .cache` してから相対パスで消すと Block された (実測)。
