# ホスト環境の一次実測

`~/.claude/CLAUDE.md` の「自分の作業でホスト環境を壊さない」カテゴリが持つ規範の、手当ての詳細と一次実測。

規範の遵守そのものには要らない。手当ての具体が要るとき、規範を疑うとき、似た失敗を踏んで「これは既知か」を確かめるときに読む。

## ホストでの大規模処理

fontTools の `TTCollection` で巨大な合体 TTC (Sarasa SuperTTC) を非 lazy 展開してメモリが 52GB まで暴走し、macOS を OOM で巻き添えに落とした。
無音を「ハング」と誤診して放置したのが増悪要因だった。

macOS の `ulimit -v` は address-space 制限が信頼できず、上限として当てにできない。
隔離先のコンテナには OrbStack か Docker を使う。

## 書き捨ての置き場 `.cache/` はツールからは本体の一部

CLAUDE.md の書き捨ての項が求める `git check-ignore` は git から見えないことしか確かめない。`.cache/` にリポジトリの複製や隔離のディレクトリを置いてツールを動かすと、ツールは ignore を見ずに親のリポジトリと同じ木として扱い、黙って件数を化けさせたり本体を書き換えたりする。

- テストランナー: vitest は既定で `.cache/` を除外しないので、`.cache/` に置いたリポジトリの複製の中のテストまで収集し、テストの件数が303から4545に化けた。`test.exclude` に `.cache/` の配下を除くグロブを足して塞いだ。既定の全体探索のままだと、書き捨ての置き場や worktree の複製の中のテストまで走る (いずれも実測。報告日は未記録、vitest の版は未記録)。報告者の提案は、`test.include` でテストの置き場を列挙すること
- pnpm: `.cache/` の下の隔離のディレクトリに専用の `pnpm-workspace.yaml` が無いと、pnpm (と corepack、`pnpm self-update`) は親の方向へ workspace を探し、リポジトリの本体の package.json の `packageManager` と lockfile を書き換えた。並列の調査 agent で3回起きた。git archive で作ったコピーのルートに専用の `pnpm-workspace.yaml` を置くと本体をルートと判定しなくなり、前後で本体の package.json と lockfile のハッシュが変わらないことを照合して確かめた (実測)
- pnpm の版: 対照のために `.cache/` の下の空のディレクトリへ package.json を置くと、`packageManager` が無いので corepack の固定ではなくホストの全体の pnpm (別のメジャー版) が走った。出力の末尾の使われた pnpm の版の行を読まないと、別の版の挙動を結論にしてしまう。写しには `packageManager` を揃える (実測)。型は `~/.claude/references/observation.md` の「対照側も同じだけ壊れる」

CLAUDE.md の委譲の項が求める隔離コピーで pnpm を使わせるときは、コピーのルートに専用の `pnpm-workspace.yaml` を置くことと、終わったら本体の package.json と lockfile のハッシュを照合することの2点を、brief に必須として書く (報告者の提案)。

## 起動したものを使い終わったら落とす

検証のためにコンテナや、MCP などが起動した Chrome を立ち上げたまま作業を終えると、黙って残ってほかの作業の邪魔になる。検証を終えた時点で落とす (Chrome の側はユーザーの申告。コンテナの側は推測で、実害の実測は無い)。

止める前に、ps でコマンド名と起動の引数を確かめ、自分が起動したものだけを選ぶ。Chrome なら MCP 専用の `user-data-dir` を引数に持つものが対象で、ユーザー自身の Chrome と、ほかのセッションの MCP サーバは止めない (実測)。

## ユーザーが開いているファイルを動かさない

ユーザーがエディタで開いていた下書きを ignore された `.cache/` へ mv で退避し、あとでその退避のディレクトリを消した。エディタは保存のたびに開いたときのパスへ書き直すので、ユーザーが保存した直しが、消したはずのディレクトリを作り直してそこに書かれた。`.cache/` は ignore されるので git status にも出ず、直しが見失われかけた (実測)。

ユーザーが開いていそうなファイルは mv で動かさない。退避が要るなら git stash かコミットで持ち、動かしたことをユーザーに伝える (実測)。

## ローカルのサービスのポート

ローカルのサービスや E2E のサーバのポートを固定するとき、既定のポートと OS の一時ポートの範囲を避ける。

- E2E の vite preview を既定の4173で起動すると、同じ機械で並行して動く別のプロジェクトのサーバとぶつかり、strictPort で起動の時点で止まった (実測)
- 一時ポートの範囲は macOS が49152〜65535 (sysctl で実測)、Linux の既定が32768〜60999 (ドキュメントのみ)。Supabase のローカル環境が自動で割り当てる帯もある (ドキュメントのみ)。これらの外、たとえば20000未満に固定すれば、外向きの接続が同じ番号を先に取って待ち受けが失敗する事故を避けられる見込み (推測。実装と検証はしていない)
