# ホスト環境とスクラッチ置き場の一次実測

`~/.claude/CLAUDE.md` の「自分の作業でホスト環境を壊さない」カテゴリが持つ規範の、
手当ての詳細と一次実測。

規範の遵守そのものには要らない。手当ての具体が要るとき、規範を疑うとき、
似た失敗を踏んで「これは既知か」を確かめるときに読む。

## ホストでの大規模処理

fontTools の `TTCollection` で巨大な合体 TTC (Sarasa SuperTTC) を非 lazy 展開して
メモリが 52GB まで暴走し、macOS を OOM で巻き添えに落とした。

ホストには VM / コンテナのような cgroup 境界が無く、暴走割り当てが OS 全体を落とす。
無音を「ハング」と誤診して放置したのが増悪要因だった。

macOS の `ulimit -v` は address-space 制限が信頼できず、上限として当てにできない。
隔離が要るときは OrbStack / Docker のメモリ上限付きコンテナを使う。

## Tirith の削除検知と .cache

`mass_file_deletion` ルールは `.cache` を削除検知の除外集合 (ビルド成果物扱い) に含む。
除外集合は tirith 側にハードコードされ設定から拡張できないので、こちらが名前を合わせる。
scratch は「まとめて消えて当然のもの」なので意味的にも正しい。

閾値の canonical は tirith 側なので `tirith explain --rule mass_file_deletion` で確認する。

### explain の文面で判定しない

explain が挙げる除外例は `node_modules` / `target` / `dist` だけで `.cache` は出てこない。
読むと「除外されない」と結論できてしまう。

実際にこの誤読が起き、「`.cache` は除外されない」と書き換えるコミットが作られた。

0.3.3 で対照付きに実測すると、`.cache` 配下は深さ 1 でも 2 でも `rm` と `rm -rf` の双方が
通り、`.cache` 外の同じ操作は CRITICAL で Block された。

対照を取らずに片側だけを見ると、ブロックされなかったことを「まだ発火していないだけ」と
読むことも、ブロックを別ルールの発火と取り違えることもできてしまう。
「報告・前提を検証済みの網羅的事実として扱わない」と同じで、
canonical を名乗る出力でも網羅とは限らない。

### 除外が効くのはコマンド文字列に現れる場合だけ

`cd .cache` してから相対パスで消すと Block された (実測)。
hook が見るのは実行後の作業ディレクトリではなくコマンド文字列なので、
除外に頼る操作ではパスを省略しない。
