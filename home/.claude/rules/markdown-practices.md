# [MUST] ドキュメントは drift を前提に書き、検査できるものは散文で規定しない

ディレクトリツリーと静的検査についての手当ての詳細と一次実測は `~/.claude/references/canonical.md` が持つ。

- README などのドキュメントにディレクトリ構成ツリーを載せないこと。経験上必ず drift する
  - rot した既存ツリーは更新ではなくセクションごと削除を優先する
- 設計ドキュメントはその時々の状況や文脈を包含するスナップショットとして無理に継続更新を行わないこと
  - 最新に保ち続けるのではなく、意図をプロダクトコードやテストコード、それらのWhy(not)コメントに乗せてそれらを更新する。収まらない事項には VCS のコミットメッセージも活用してよい
  - ただしプロダクト全体のデザインや運用ドキュメントは実際に使用するものであり、現状のコードと drift すると実害が出るため、例外として更新する
- 静的検査可能なルールはプロンプトではなく、その環境の linter か ast-grep で記述する
  - 末尾改行 (1つの空行) や行末空白のような正規化は各環境の formatter/linter が担保する前提とし prose では個別に規定しない
